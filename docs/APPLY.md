# 챗봇으로 신청하기 (`/api/apply/*`) — 설계

조이와 대화하다가 정책·프로그램을 골라 신청까지 가는 흐름이다. FE와 BE가 같이 보고 구현하는 문서다.

- 상태 (2026-11-21): **① 대신 제출(구글폼) API 구현** — `/api/apply/start`·`draft`·`submit`, 추천·대화 결과의 `apply_channel`(지금은 `form` 또는 `null`). **②③④ 갈래, 대화의 신청 버튼, FE 화면은 아직**. 실제 구현 형식은 9-5장, 개인정보 줄이기(FE 채우기·치환·AI 전달 내용 보기)는 9-6장. 정해지지 않은 것은 13장.
- 범위: **시연·MVP용**. 실제 기관 구글폼에는 제출하지 않고, 우리가 원본을 따라 만든 **테스트용 구글폼**에만 제출한다(회의록: 실제 신청은 기관에 민폐라서). 그 밖의 사이트는 사용자가 직접 로그인·제출한다.
- 저장: 하지 않는다(로그인 없는 MVP). 진행 중인 답·신청 기록은 FE가 로컬에 둔다. DB 영향은 10장.
- 관련 문서: 대화 API [CHAT.md](CHAT.md), 기획 원칙 [requirements.md](requirements.md) 4·6장, 크롤러 [CRAWLER.md](CRAWLER.md)

## 1. 한 가지 약속과 원칙

**조이가 할 수 있는 만큼 대신 하고, 사람이 해야 하는 부분만 넘긴다.** 사용자에게는 항상 같은 흐름(신청할까요? → 준비 → 신청 → 기록)이고, 신청 방식에 따라 조이가 해 주는 범위만 달라진다.

- **신청은 정해진 단계로 진행한다.** 피클처럼 신청할 때는 자유 대화보다 선택지를 보여 준다. 단계·검증·제출은 서버 규칙이 하고 LLM은 끼어들지 않는다.
- **사용자 확인 없이는 어떤 폼도 제출하지 않는다.** 최종 요약을 보여 주고 사용자가 [제출하기]를 눌렀을 때만 제출한다. 폼을 읽는 것은 제출이 아니다.
- **로그인과 다른 사이트의 최종 제출은 사용자가 한다.** 정부24·복지로·고용24·서울시 공공서비스예약 등은 로그인(간편인증·공동인증서·통합회원)이 필요하다. 서버는 사용자 비밀번호·인증서를 받지 않는다. 공공서비스예약은 자동 접속을 "비정상 접근"으로 차단한다(2026-11-21 확인).
- **동의 문항은 대신 답하지 않는다.** 동의 내용을 그대로 보여 주고 사용자가 직접 고른다.
- **LLM은 초안만 쓴다.** 지원 동기·전화 대본·문의 문구. 사용자가 말하지 않은 경험·자격·숫자는 넣지 않는다. 신청 방법·서류·연락처는 수집한 데이터에서만 가져온다.
- **이미 아는 정보는 묻지 않는다.** 기본 정보로 채우고 확인만 받는다.
- **완료는 누가 확인했는지 구분한다.** 조이가 제출에 성공한 것(`confirmed_by: server`)과 사용자가 "신청했어요"라고 알려 준 것(`confirmed_by: user`)을 나눠 기록·표시한다. AI가 신청 완료를 임의로 확정하지 않는다(requirements.md 6장).
- **비밀 정보는 Git에 올리지 않는다.** 테스트 폼 주소·팀원 전화번호는 로컬 파일(9장)과 `.env`에만 둔다.

## 2. 네 갈래

```text
찾기 → 고르기 → 조이: 「○○」 신청할까요?  [신청하기] [나중에]
                         │
      ┌──────────────────┼──────────────────┬──────────────────┐
  ① 대신 제출         ② 같이 신청          ③ 대신 준비        ④ 바로 가기
  form                guide                prepare            visit
  (구글폼)            (온라인 사이트·       (전화·카톡·이메일·  (방문형,
                       공공서비스예약)       SNS·방법 안 적힘)   신청 없음)
      └──────────────────┴──────────────────┴──────────────────┘
                         │
     공통 마무리: 신청 기록 + 일정 추가 + 나중에 "결과 나왔어요?" (7장)
```

| 갈래 (`apply_channel`) | 조이가 하는 일 | 사용자가 하는 일 | 완료 기록 |
| --- | --- | --- | --- |
| ① `form` 대신 제출 | 폼 문항 읽기, 기본 정보 채우기, 모르는 것만 질문, 긴 글 초안, 제출 | 확인 후 [제출하기] | `server` (제출 성공) |
| ② `guide` 같이 신청 | 신청 페이지 바로 열기, 준비물·서류, 단계별 화면 안내, 답변 초안·[복사] | 로그인, 사이트에서 최종 [신청] | `user` ([신청 완료!]) |
| ③ `prepare` 대신 준비 | 연락처, 전화 대본, 카톡·이메일·DM 문구 초안 | 전화·메시지 보내기 | `user` |
| ④ `visit` 바로 가기 | "신청 없이 가면 돼요" + 장소·시간·준비물 | 방문 | 일정에만 추가 |

[대신 전화해 줘]는 "아직 구현되지 않은 기능이에요"로 안내한다(회의록: 전화는 확장 기능, 배포 준비 후 시도).

### 2-1. 갈래 정하기 (규칙, LLM 없음)

크롤러·적재 단계에서 항목마다 `apply_channel`을 정한다. 위에서부터 처음 맞는 것.

| 순서 | 조건 | 갈래 |
| --- | --- | --- |
| 1 | 신청 링크가 구글폼이고 9장 신청서 목록에 있음 | `form` |
| 2 | 방문형(`access_type=visit`) 또는 본문에 "예약 없이·현장 방문·자유롭게 방문" | `visit` |
| 3 | 신청 링크가 온라인 신청 사이트(공공서비스예약·정부24·복지로·고용24·온통청년·네이버폼·센터 홈페이지·로그인 필요 구글폼 등), 또는 본문에 "공공서비스예약에서 검색" | `guide` |
| 4 | 본문에 전화·카톡·이메일·DM 신청, SNS 링크만 있음, 신청 방법이 안 적힘 | `prepare` |

목록에 없는 실제 기관 구글폼은 MVP에서 `guide`(링크 열기 + 안내)로 둔다. 실제 기관 폼에 조이가 제출하는 것은 기관 협의 뒤 확장 기능이다.

대략의 수 (2026-11-21, 서비스 대상 프로그램 169개): 구글폼 47(그중 테스트 폼에 연결한 것만 `form`) · 다른 사이트·예약 약 50 · SNS·연락처·방법 없음 약 45 · 방문형 약 23. 정책 2,335개는 대부분 `guide`(신청 URL 810개, 신청 방법 글 1,304개).

## 3. ① 대신 제출 — 구글폼

```text
① 조이: 「○○ 프로그램」 신청할까요?                    [신청하기] [나중에]
② 조이: 이 정보로 신청할게요.
        이름 김둘셋 · 만 24세 · 여 · 서울 관악구           [맞아요] [고칠래요]
③ 모르는 것만 하나씩
   - 고르는 문항  → 선택지 버튼 (기타가 있으면 직접 입력)
   - 짧은 답      → 입력 칸 (+ 폼의 작성 안내, 예: "동까지 필수")
   - 긴 답        → 조이: 신청 이유를 적어야 하네요. 초안 써 드릴까요?   [써 줘요] [직접 쓸게요]
                    → 초안                         [이대로] [다시 써 줘] [직접 고칠게요]
   - 동의         → 동의 내용 그대로                [동의합니다] [동의하지 않습니다]
   - 모를 때      → [잘 모르겠어요] → "이건 센터에 물어봐야 알 수 있어요. 물어볼까요?" → ③ 대신 준비로
④ 조이: 이렇게 제출할게요. (문항별 답 요약)        [제출하기] [수정하기]
⑤ 성공 → 조이: 신청 완료됐어요! 결과는 센터에서 연락이 올 거예요.   → 7장 마무리
   실패 → 조이: 제출이 안 됐어요. 잠시 뒤 다시 해 볼까요?          [다시 제출]
```

### 3-1. 신청할 수 있는 구글폼, 없는 구글폼

2026-11-21에 실제 서울청년센터 구글폼 두 개를 읽어 확인했다(제출하지 않음).

| 폼 | 처리 |
| --- | --- |
| 로그인 없이 열리는 한 페이지 폼, 문항이 짧은 답·긴 답·하나 고르기·여러 개 고르기·드롭다운·날짜 | **신청 가능**. 예: 서울청년센터 동대문 「11월의 뜸 <베이킹편>」 — 성명·만 나이·성별·연락처·거주지역(동까지)·신청 이유(긴 답)·알게 된 경로(선택, 기타)·개인정보 동의 |
| 마감된 폼 | 마감 안내(아래). 응답을 닫은 폼은 열면 `closedform`으로 넘어가고 기관 마감 문구가 나온다 |
| 로그인 필요(구글 계정·응답 1회 제한)·파일 올리기·여러 페이지 | `guide`로 (링크 열기 + 안내) |

마감일 때

```text
조이: 아쉽게도 이 신청은 마감됐어요.
조이: 기관 안내로는 "상담 예산 소진으로 더 이상 신청을 받지 않는다"고 해요. 비슷한 지원을 찾아볼까요?
                                                    [비슷한 지원 찾기] [다른 추천 보기]
```

- 기관 마감 문구는 있을 때만 그대로 옮긴다.
- 추천 단계에서 신청 기간이 지난 항목은 빠지지만, 예산 소진처럼 일찍 닫힌 폼은 이 확인으로만 알 수 있다.

## 4. ② 같이 신청 — 온라인 사이트·공공서비스예약

```text
① 조이: 「보여줘! 강북홈즈」는 서울시 공공서비스예약에서 신청해요.
        같이 해 볼까요? 단계마다 알려 드릴게요.                    [같이 신청하기] [나중에]
② 준비물
   조이: 신청 전에 준비할 거예요.
         ☐ 서울시 통합회원 로그인   ☐ (정책이면) 주민등록등본·소득 증빙 등 제출 서류
   써야 하는 글이 있으면 → 초안 + [복사]
③ [신청 페이지 열기]  ← 검색 없이 그 항목 페이지로 바로 (새 창, 대화는 그대로)
④ 화면 따라가기 (사이트별 단계, 4-1)
   조이: 1/4 오른쪽 위 '로그인'을 눌러 로그인해 주세요.        [했어요] [막혔어요]
   조이: 2/4 '예약하기'를 눌러 주세요.                          [했어요] [막혔어요]
   조이: 3/4 이용 약관을 읽고 동의해 주세요.                     [했어요]
   조이: 4/4 추가 질문에는 이렇게 적으면 돼요. "…" [복사]
         다 됐으면 '신청' 버튼을 눌러 주세요.                  [신청 완료!] [막혔어요]
⑤ [신청 완료!] → 7장 마무리 (confirmed_by: user)
   [막혔어요]  → "어느 단계에서 막혔어요?" → 도움말, 그래도 안 되면 → ③ 대신 준비(센터 문의)
```

### 4-1. 사이트별 단계 안내

- 사이트마다 화면 순서가 달라 **사이트별 단계 목록**을 미리 만든다(BE 파일, 사람이 확인하고 작성). 화면이 바뀌면 고쳐야 하므로 시연 대상 사이트부터 만든다.
- MVP: **서울시 공공서비스예약** 하나. 나머지 사이트는 "공식 페이지 열기 + 일반 단계(로그인 → 신청 → 서류 제출 → 완료 확인)".
- 확장: 정부24·복지로·고용24·온통청년·네이버폼.

### 4-2. 정확한 신청 페이지 찾기

- 신청 링크가 있으면 그 주소(단축 링크는 크롤러가 풀어 둠, CRAWLER.md).
- 본문에 "공공서비스예약에서 '○○' 검색"만 있으면: 서울 열린데이터광장의 **공공서비스예약 Open API**로 서비스 목록(서비스 ID·주소)을 받아 제목으로 맞춘다. 사이트를 긁지 않는다(자동 접속 차단).
- 못 찾으면 사이트 첫 화면 링크 + "'○○'를 검색해 주세요".

## 5. ③ 대신 준비 — 전화·카톡·이메일·SNS·방법 없음

```text
조이: 이건 전화로 신청해요. 서울청년센터 강북 02-xxx-xxxx (평일 10~17시)
      할 말을 정리해 드릴까요?                     [대본 써 줘] [대신 전화해 줘] [나중에]
  [대본 써 줘]      → 대본 (인사 → 신청하려는 프로그램 → 확인할 것 → 전달할 내 정보)  [복사]
  [대신 전화해 줘]  → "아직 구현되지 않은 기능이에요. 대본을 드릴게요."
조이: 신청하셨어요?                                [했어요] [아직] [못 했어요]
```

- 카톡·이메일·인스타 DM이면 대본 대신 **보낼 문구 초안** + [채널 열기].
- 신청 방법이 안 적혀 있으면: "공고에 신청 방법이 안 적혀 있어요. 센터에 물어볼까요?" → 문의 대본 + 공식 페이지. 회의록의 "필요한 정보가 없어? 그러면 전화할까요?" 흐름.
- 연락처는 수집한 본문에서만 가져온다. 시연용 전화 연결 번호는 팀원 번호로, `.env`에만 둔다.

## 6. ④ 바로 가기 — 방문형

```text
조이: 이건 따로 신청 없이 가면 돼요. 서울청년센터 양천 · 11월 17일(화) 17~19시
      준비물: 없음                                  [일정에 추가] [길 찾기]
```

## 7. 공통 마무리

```text
조이: 신청 기록에 남겨 둘게요. 결과 발표일이나 참여일을 일정에 넣을까요?   [일정에 추가] [괜찮아요]
(나중에 다시 왔을 때)
조이: 지난번 「○○」 결과 나왔어요?                [붙었어요] [떨어졌어요] [아직]
```

- 신청 기록은 FE 로컬에 둔다(지금 마이페이지 신청 기록과 같은 곳). 기록에 `apply_channel`·`confirmed_by`를 함께 둔다.
- "결과 나왔어요?"는 FE가 다음 방문 때 기록을 보고 띄운다(서버 알림 없음).

## 8. 누가 무엇을 하나

| 단계 | FE | BE |
| --- | --- | --- |
| 시작 | 카드에 [신청하기] (모든 항목. 갈래에 따라 버튼 문구만 다름), 누르면 `start` | 갈래 판단, 갈래별 말풍선·버튼·데이터 |
| ① 질문·확인·제출 | 문항을 하나씩 말풍선으로, 답 모으기, 요약, `submit` | 폼 읽기, 기본 정보 채우기, 검증, 구글폼 제출 |
| ② 단계 안내 | 신청 페이지 새 창 열기, 단계 말풍선·[했어요]/[막혔어요] 진행, [복사] | 신청 페이지 주소, 준비물, 사이트별 단계 |
| ②③ 초안 | [써 줘요]·[대본 써 줘]면 `draft`, 결과를 수정 칸에 | LLM 초안 |
| ③ 연락 | 전화 걸기(tel:)·채널 열기 링크 | 연락처, 대본 |
| ④ 방문 | 일정 추가 | 장소·시간 |
| 마무리 | 신청 기록·일정 저장(로컬), 다음 방문 때 결과 확인 | 없음 |

진행 상태는 FE가 가진다. 서버는 매 요청을 그것만 보고 처리한다(대화 API와 같은 방식).

## 9. API

`applicant`는 신청할 때만 보내는 개인정보다. 서버는 저장·로그 기록을 하지 않고, ① 구글폼 제출에만 쓴다. `profile`·`checkin`은 [CHAT.md](CHAT.md) 4장과 같다.

```json
"applicant": {"name": "김둘셋", "birth_date": "2001-03-05", "phone": "010-0000-0000", "email": null}
```

### 9-0. 지금 구현된 것 (FE 연결용 요약)

| API | 구현 | 비고 |
| --- | --- | --- |
| `POST /api/recommendations`, `POST /api/chat` 결과 항목의 `apply_channel` | ✅ | 신청서 목록에 있으면 `"form"`, 아니면 `null`. `"form"`이면 카드에 [신청하기] |
| `POST /api/apply/start` | ✅ ① form | 목록에 없는 항목은 `channel: null, available: false, reason: "not_supported"` + `official_url` (②③④ 안내는 아직) |
| `POST /api/apply/draft` | ✅ ① 긴 답만 (`kind` 필드 없음) | 전화 대본·메시지(`call_script`·`message`)는 아직 |
| `POST /api/apply/submit` | ✅ | |
| `apply_method`·`documents`·`contacts`, 대화의 `apply` 버튼 | ❌ | 14장 2·6번 |

시연용 항목 id: `demo:open`(신청 가능 테스트 폼), `demo:closed`(마감 테스트 폼). 연결할 실제 프로그램이 정해지면 그 id 로 바꾼다.

### 9-1. 기존 API에 붙는 것

추천(`/api/recommendations`)·대화(`/api/chat`) 결과의 정책·프로그램 항목에 추가:

| 필드 | 설명 |
| --- | --- |
| `apply_channel` | `form` / `guide` / `prepare` / `visit` (2-1) |
| `apply_method` | 신청 방법 한두 문장 (정책: 온통청년 신청 방법, 프로그램: 본문의 "신청 방법" 문장). 없으면 `null` |
| `documents` | 제출 서류 목록 (정책만, 없으면 `[]`) |
| `contacts` | `[{"type": "phone", "value": "02-…", "label": "서울청년센터 강북"}]` (`phone` / `kakao` / `email` / `sns`) |

대화에서 "이거 신청할래"라고 하면 `choices`에 버튼이 온다. FE는 누르면 `start`를 호출한다(사용자 메시지로 보내지 않음).

```json
{"type": "apply", "label": "「청년 마음 산책」 신청하기", "item_id": "program:abc123"}
```

### 9-2. `POST /api/apply/start` — 신청 시작 (모든 갈래)

요청: `{"item_id": "program:abc123", "applicant": {...}, "profile": {...}}`

응답 공통: `channel`, `item`(`id`, `title`), `replies`, `choices`. 갈래별 추가 필드:

**① form**

```json
{
  "channel": "form", "available": true,
  "filled": [{"question_id": "q1", "label": "성명", "value": "김둘셋"}],
  "questions": [
    {"id": "q5", "label": "거주지역 (ex.OO구 OO동)", "kind": "short", "required": true,
     "hint": "반드시 \"동\"까지 필수기재", "prefill": "관악구 ", "prompt": "사는 동까지 알려 주세요."},
    {"id": "q6", "label": "신청하신 이유", "kind": "long", "required": true, "can_draft": true,
     "prompt": "신청 이유를 적어야 하네요. 초안 써 드릴까요?"},
    {"id": "q8", "label": "개인정보 동의", "kind": "agree", "required": true, "description": "(동의 내용 원문)",
     "options": ["동의합니다.", "동의하지 않습니다."]}
  ]
}
```

| 필드 | 설명 |
| --- | --- |
| `filled` | 기본 정보로 채운 문항. ② 확인 말풍선에 쓰고, [고칠래요]면 FE가 고쳐서 제출 때 보낸다 |
| `questions` | 물어야 할 문항(순서대로). `kind`: `choice` / `multi` / `short` / `long` / `agree` / `date`. `other`: 기타 있음. `hint`: 폼의 작성 안내. `prefill`: 일부 채운 값. `prompt`: 조이 말풍선. `can_draft`: [써 줘요] |

마감·열 수 없음: `{"channel": "form", "available": false, "reason": "closed" | "unreachable", "closed_message": "…", "official_url": "…"}`

**② guide**

```json
{
  "channel": "guide",
  "site": "yeyak_seoul",
  "open_url": "https://yeyak.seoul.go.kr/…",
  "prepare": ["서울시 통합회원 로그인", "주민등록등본"],
  "steps": [
    {"text": "오른쪽 위 '로그인'을 눌러 로그인해 주세요.", "choices": ["했어요", "막혔어요"]},
    {"text": "'예약하기'를 눌러 주세요.", "choices": ["했어요", "막혔어요"]},
    {"text": "추가 질문에는 이렇게 적으면 돼요.", "draft_for": "motive", "choices": ["신청 완료!", "막혔어요"]}
  ],
  "help": {"막혔어요": "어느 단계에서 막혔어요? 센터에 물어볼 수도 있어요."}
}
```

`site`가 단계 목록이 없는 사이트면 `steps`는 일반 단계(로그인 → 신청 → 서류 → 완료 확인).

**③ prepare**

```json
{"channel": "prepare", "contacts": [{"type": "phone", "value": "02-…", "label": "서울청년센터 강북", "hours": "평일 10~17시"}],
 "drafts": ["call_script"], "official_url": "…"}
```

`drafts`: 만들 수 있는 초안 종류(`call_script` 전화 대본 / `message` 카톡·이메일·DM 문구). `choices`에 [대신 전화해 줘]가 오고, 누르면 "아직 구현되지 않은 기능이에요"(FE 고정 문구 또는 `start`가 준 `replies`).

**④ visit**

```json
{"channel": "visit", "place": "서울청년센터 양천", "when": "11월 17일(화) 17:00~19:00", "bring": [], "map_query": "서울청년센터 양천"}
```

### 9-5. ① 구현된 형식 (2026-11-21)

`start` 요청: `{"item_id": "demo:open", "applicant": {"name", "birth_date": "YYYY-MM-DD", "phone", "email"}, "profile": {...}}` (`applicant`·`profile` 은 없어도 됨 → 모두 질문으로 온다)

`start` 응답 (신청 가능, 실제 테스트 폼으로 확인한 값)

```json
{
  "channel": "form", "available": true,
  "item": {"id": "demo:open", "title": "[둘셋 테스트] 11월 청년 베이킹 클래스 참여자 모집"},
  "filled": [{"question_id": "q1", "label": "성명", "value": "김둘셋"}, {"question_id": "q2", "label": "만 나이", "value": "24"},
             {"question_id": "q3", "label": "성별", "value": "여"}, {"question_id": "q4", "label": "연락처", "value": "010-0000-0000"}],
  "questions": [
    {"id": "q5", "kind": "long", "required": true, "prompt": "사는 동까지 알려 주세요. (관악구 ○○동)", "prefill": "관악구 ", "label": "거주지역 …"},
    {"id": "q6", "kind": "long", "required": true, "prompt": "신청 이유를 적어야 하네요. 초안 써 드릴까요?", "can_draft": true, "hint": "…"},
    {"id": "q7", "kind": "choice", "required": false, "prompt": "프로그램을 알게 된 경로를 알려주세요. (안 적어도 돼요)",
     "options": ["센터 블로그", "…"], "other": true},
    {"id": "q8", "kind": "agree", "required": true, "prompt": "개인정보 동의 내용을 읽어 보고 직접 골라 주세요.",
     "options": ["동의합니다.", "동의하지 않습니다.(…)"], "description": "(동의 내용 원문)"}
  ],
  "replies": ["「…」 신청서를 같이 써 볼게요.", "알고 있는 정보로 채웠어요. 성명 김둘셋 · 만 나이 24 · 성별 여 · 연락처 010-0000-0000"],
  "choices": [{"type": "apply_confirm", "label": "맞아요"}, {"type": "apply_edit", "label": "고칠래요"}]
}
```

- `choices.type`: `apply_confirm`(다음 문항으로) / `apply_edit`(채운 값 수정 칸) / `message`(`text`를 대화로 보냄) / `record`(신청 기록·일정 저장) / `draft_accept`·`draft_retry`·`draft_edit`(초안 버튼).
- 마감: `{"channel": "form", "available": false, "reason": "closed", "closed_message": "…", "replies": [...], "choices": [비슷한 지원 찾기, 다른 추천 보기]}`
- 열 수 없음·지원 안 되는 폼: `reason: "unreachable" | "not_supported"`, `official_url`(있으면).

`draft` 요청: `{"item_id", "question_id": "q6", "messages": [대화], "profile", "checkin", "previous": "다시 써 줘일 때"}` → `{"question_id", "draft", "replies", "choices"}`. 오류: LLM 없음·실패 503 `AI_UNAVAILABLE`, 초안 대상이 아닌 문항 404 `APPLY_NOT_AVAILABLE`, 폼 마감 409 `APPLY_FORM_CLOSED`.

`submit` 요청: `{"item_id", "applicant", "answers": {"q1": "김둘셋", …, "q7": "직접 쓴 기타 답도 가능"}}` (`filled`의 값 + `questions`의 답. `multi`는 배열) → `{"status": "submitted", "confirmed_by": "server", "submitted_at", "item", "replies", "choices"}`. 오류: 422 `APPLY_INVALID`(`missing`·`invalid` 문항 id, 제출하지 않음) / 409 `APPLY_FORM_CLOSED` / 404 `APPLY_NOT_AVAILABLE` / 502 `APPLY_SUBMIT_FAILED`.

### 9-6. 개인정보 줄이기: FE 채우기 · 치환 · AI 전달 내용 보기 (2026-11-21)

개인정보가 BE 를 지나는 때는 **[제출하기]를 누른 순간 한 번**뿐이다(구글폼 제출은 BE 가 대신 한다 — 성공 확인·테스트 폼 주소 보호. 저장·로그 없음).

```text
FE                                         BE                         구글폼
start {item_id, profile} ────────────────► 폼 읽기
◄── questions (이름·생일·연락처·이메일 칸에 fill_key)
FE 가 기기 값으로 채움 → "이 정보로 채웠어요 [맞아요][고칠래요]"
(초안) 이름·생일·연락처·이메일 → [이름]·[생년월일]·[연락처]·[이메일] 로 바꿈
  [AI에 전달되는 내용 보기] → draft {…, preview: true} → ai_input (LLM 안 부름)
draft {…치환된 messages} ────────────────► LLM
◄── draft ("[이름]입니다 …"), placeholders: ["[이름]"]
FE 가 자리 표시를 기기 값으로 되돌림
[제출하기] → submit {answers} ───────────► 검증·제출 ───────────────► 
```

- `start`: `applicant` 는 보내지 않아도 된다(보내면 예전처럼 BE 가 채워 `filled` 로 준다, 호환). `questions`/`filled` 의 개인정보 칸에 `fill_key`: `name` / `birth_date`(폼에는 `YYYY.MM.DD`) / `phone` / `email`. FE 에 값이 있으면 채우고 확인만, 없으면 `prompt` 로 묻는다. 나이·성별·거주지는 `profile` 로 BE 가 채운다.
- `draft` 요청에 `preview: true` → `{"question_id", "ai_input": "LLM 에 보낼 글 그대로"}`. LLM·사용량 제한 없음, LLM 키가 없어도 된다.
- `draft` 응답에 `placeholders`: 초안에 들어간 자리 표시 목록. AI 는 자리 표시를 꼭 필요할 때만 그대로 쓰고 값을 짐작하지 않는다.
- 안전망: FE 치환이 빠져도 BE 가 LLM 에 보내기 전 휴대폰 번호·이메일을 `[연락처]`·`[이메일]` 로 가린다(이름은 BE 가 알아볼 수 없어 FE 치환이 맡는다).

### 9-3. `POST /api/apply/draft` — 초안 (①②③ 공용)

요청

```json
{"item_id": "program:abc123", "kind": "form_answer" | "call_script" | "message",
 "question_id": "q6", "messages": [...], "profile": {...}, "checkin": {...}, "previous": "다시 써 줘일 때 이전 초안"}
```

응답: `{"draft": "…", "replies": ["이렇게 써 봤어요. 고칠 데 있으면 고쳐 주세요."]}`

- 재료: 대화, 상태 체크 답, 기본 정보(이름·연락처 제외), 항목 소개·신청 방법. 사용자가 말하지 않은 경험·자격·숫자는 넣지 않는다.
- `call_script`·`message`에 들어갈 이름·연락처 자리는 `[이름]`·`[연락처]`로 비워 두고 FE가 로컬 값으로 채운다(LLM에 개인정보를 보내지 않음).
- 실패 → 503 `AI_UNAVAILABLE`. FE는 "직접 써 주세요".

### 9-4. `POST /api/apply/submit` — 제출 (① form만)

요청: `{"item_id": "program:abc123", "applicant": {...}, "answers": {"q1": "김둘셋", "q5": "관악구 신림동", ...}}`

응답: `{"status": "submitted", "submitted_at": "2026-11-21T15:02:11+09:00", "confirmed_by": "server", "replies": ["신청 완료됐어요!", "…"]}`

| 오류 | 응답 | FE |
| --- | --- | --- |
| 필수 답 없음·선택지 밖 값 | 422 `APPLY_INVALID` + `missing` | 그 문항으로 돌아가 다시 묻기 |
| `form` 갈래가 아님 | 404 `APPLY_NOT_AVAILABLE` | `start` 결과대로 안내 |
| 구글폼 제출 실패 | 502 `APPLY_SUBMIT_FAILED` | "제출이 안 됐어요" + [다시 제출] |

②③ 갈래의 "신청 완료"는 서버로 보내지 않는다(FE 로컬 기록, `confirmed_by: user`).

## 10. 데이터와 DB

### 10-1. MVP: migration 없음

| 필요한 것 | 어디에 | DB 변경 |
| --- | --- | --- |
| `apply_channel`·`apply_method`·`documents`·`contacts` | `catalog_items.payload`(JSONB)에 같이 넣는다 | **없음**. payload는 서비스 JSON 항목 전체라 칸을 추가하면 그대로 들어간다. 갈래로 걸러 찾을 일이 생기면 그때 컬럼 추가 |
| 정책 신청 방법·제출 서류·심사 방법 | 이미 payload에 있다(온통청년 원본) | 없음. 추천 결과로 꺼내 주기만 하면 된다 |
| 프로그램 신청 방법 문장·연락처 | 크롤러가 본문에서 뽑아 serving JSON → payload | 없음. 크롤러·분류 단계 수정 |
| 테스트 구글폼 주소 | BE 로컬 파일(9장 아래) | 없음. 비밀이라 DB에도 넣지 않음 |
| 사이트별 단계 안내 | BE 코드 안 파일(사람이 작성) | 없음 |
| 신청 기록·일정 | FE 로컬 | 없음 (로그인 없는 MVP) |

### 10-2. 확장 (로그인 도입 후, 문서로만)

[DATABASE.md](DATABASE.md) 6장 계획 테이블에 반영:

- `activity_records`에 `apply_channel`, `confirmed_by`(`server`/`user`), `submitted_at` 추가.
- `user_consents.consent_type`에 `apply_submit`(조이가 기관 신청서에 내 정보를 대신 제출하는 것에 대한 동의) 추가. 실제 기관 폼 대리 제출을 할 때 필요.
- 피클처럼 사이트 로그인까지 대신 하려면 사용자 기기 안에 암호화해 보관하는 방식이 필요하다(서버 DB에 비밀번호를 두지 않음). MVP 범위 밖.

## 11. 신청서 목록 (① form, BE 로컬 파일, Git에 올리지 않음)

`.env`의 `APPLY_FORMS_PATH`가 가리키는 JSON. 저장소에는 가짜 값 예시만 올린다.

```json
{"program:abc123": {"form_url": "https://docs.google.com/forms/d/e/<비공개>/viewform"}}
```

- **문항은 적지 않는다.** 서버가 `start` 때 폼을 열어 문항·문항 번호·필수 여부·선택지·작성 안내를 읽는다. 구글 공개 API가 아니라 폼 페이지에 들어 있는 값이라, 형식이 바뀌어 읽기가 실패하면 `unreachable`로 안내한다.
- 기본 정보로 채우는 규칙 (문항 제목의 단어)

| 문항 제목에 있으면 | 채우는 값 | 비고 |
| --- | --- | --- |
| 성명·이름 | `applicant.name` | |
| 나이 | `profile.age` | |
| 생년월일 | `applicant.birth_date` | |
| 성별 | `profile.sex` | 선택지와 맞을 때만 |
| 연락처·휴대폰·전화 | `applicant.phone` | |
| 이메일 | `applicant.email` | |
| 거주지·사는 곳 | `profile.sigungu_cd`의 이름 | "동까지"면 구까지 `prefill`하고 묻는다 |
| 동의 | 채우지 않음 | 항상 묻는다 |

- 제출: 폼의 공개 제출 주소(`formResponse`)에 문항 번호=답 + 폼 페이지의 숨은 값(`partialResponse`·`fbzx`·`submissionTimestamp` 등, 브라우저와 같게). 성공은 접수 완료 화면(입력 폼이 다시 나오지 않음)으로 판단한다. 폼은 "로그인 필요"·"응답 1회 제한"을 끈다.
- 테스트 폼 만들기: [`scripts/create_test_forms.gs`](../scripts/create_test_forms.gs)를 구글 Apps Script에서 실행하면 실제 청년센터 신청서와 같은 양식의 테스트 폼 2개(신청 가능·마감)가 생긴다.

## 12. 개인정보

- 이름·생년월일·연락처는 FE 로컬에 있고 ① [제출하기]를 누를 때만 BE로 보낸다(`start` 에는 보내지 않고 FE 가 `fill_key` 로 채운다, 9-6). BE는 저장·로그 기록을 하지 않는다.
- ② 같이 신청은 사용자가 공식 사이트에 직접 입력하므로 개인정보가 BE 로 오지 않는다.
- LLM(초안)에는 이름·연락처를 보내지 않는다. FE 가 자리 표시로 바꿔 보내고 되돌리며, 보내기 전에 [AI에 전달되는 내용 보기]로 확인할 수 있다(9-6).
- ① 제출 대상은 우리가 만든 테스트 폼뿐.
- **대회 원칙: 실제 개인정보 금지 → 가상·샘플 데이터** (공식 첨부 '대회 안내문'·'프로젝트 소개서 양식', `../docs/프로젝트소개서_초안.md`). 시연·테스트 폼 응답·화면 캡처·대화 예시는 가상 페르소나 정보로만 채운다(이름 예: 김둘셋, 연락처 예: 010-0000-0000). 소스코드 저장소 링크를 심사용으로 낼 수 있으므로 저장소에도 실제 개인정보를 두지 않는다.

Git에 올려도 되는 것 / 안 되는 것

| 항목 | Git | 이유 |
| --- | --- | --- |
| 실제 청년센터·정책 공고의 신청 링크(구글폼 포함) | 올려도 됨 (이미 `data/seed`에 있음) | 기관이 공개한 공고 정보. 개인정보가 아니다 |
| 팀원 전화번호(전화 연결 시연용) | **안 됨** → `.env` | 개인정보 |
| 우리 테스트 구글폼 응답용 주소 | 안 올림 → `apply_forms.local.json`, 배포 때는 환경변수 | 개인정보는 아니지만, 주소가 퍼지면 누구나 응답을 넣을 수 있어 시연 중 장난 응답이 보일 수 있다 |
| 테스트 구글폼 편집용 주소 | 안 됨 (BE에 필요 없음) | 만든 사람의 구글 계정에 묶인 관리 주소 |
| 테스트 폼에 들어온 응답(내보낸 파일·캡처) | **안 됨** | 신청자 정보. 시연 뒤 폼에서 응답을 지운다(폼의 동의 문구 "시연 종료 후 즉시 삭제") |

## 14. 구현 순서 (BE)

1. ✅ **① 대신 제출**: 신청서 목록, 구글폼 읽기(문항·마감), `start`(form), `submit`, `draft`(form_answer) — 2026-11-21. 실제 테스트 폼으로 `start`(신청 가능·마감) 확인. 실제 제출·실제 LLM 초안은 아직 확인 전
2. **공통 데이터**: `apply_channel` 규칙, 프로그램 신청 방법·연락처 추출(크롤러), 정책 신청 방법·서류 꺼내기, 추천·대화 결과에 9-1 필드
3. **② 같이 신청**: 공공서비스예약 단계 안내·주소 찾기(Open API), 나머지는 일반 단계
4. **③ 대신 준비**: `draft`(call_script·message)
5. **④ 바로 가기**
6. 대화 API에 `apply` 버튼 연결
7. 테스트(저장한 폼 페이지로 읽기·마감, 가짜 제출 서버, 갈래 규칙) + 페르소나 3명 시연 흐름
