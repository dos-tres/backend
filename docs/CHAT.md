# AI 비서 대화 (`POST /api/chat`)

사용자의 짧은 말에서 상태·관심 분야·찾는 지원을 알아듣고, 정책·프로그램 추천(규칙 엔진)이나 검색으로 이어 준다. 말투는 일을 대신 해 주고 결과를 알려 주는 비서(피클 참고). 2026-11-20 기준, 프롬프트 `chat-v3`.

- 구현 완료: 대화 API, 위기 신호 규칙, LLM 추출(상태 체크 답·관심 분야·의도·검색어·제안), 말풍선 여러 개, 서버가 만드는 결과 말풍선, 제안 버튼, 추천·검색 연결, 오류 처리, 테스트
- 검증: 위기 규칙 32/32·오탐 0, LLM 점검 28개 × 3회 84/84, 여러 턴 시나리오 19개 (7장, [CHAT_SCENARIOS.md](CHAT_SCENARIOS.md))
- 계획: 대화 저장(로그인 도입 이후), FE 화면 연결, 사용량 상한·요청 빈도 제한, 위기 대응 문구 전문가 검토, 전화 문의 대행
- 배포: 하지 않음

## 1. 흐름

```text
FE ─ messages(지금까지 대화) + profile(있으면) + checkin(지금까지 답) ─▶ POST /api/chat
  1) 위기 신호 확인 (규칙, LLM 없음) ── 걸리면 → 연락처 안내 말풍선(mode=crisis)으로 바로 응답
  2) LLM: 말풍선 + 상태 체크 답 + 관심 분야 + 의도(intent) + 검색어 + 다음 질문/제안  (JSON, 선택지 code 로만)
  3) 서버가 LLM 결과 검증·정리
     - 없는 문항·선택지·관심 분야는 버림
     - 이미 답한 문항을 다시 묻는 문장은 뺌
     - 사용자가 찾아 달라고 하지 않았는데 추천·나이 질문으로 넘어가면 → 상황 이야기 + 제안 버튼으로 바꿈
  4) intent=recommend → 추천 엔진(app/recommend, /api/recommendations 와 같은 계산)
     intent=search    → 검색어로 DB/서비스 JSON 검색 (특정 대상 사업도 포함)
     profile 이 없으면 → needs=["profile"] (FE 가 나이·거주지 입력 칸을 띄움)
  5) 결과가 있으면 서버가 실제 결과로 결과 말풍선을 만들어 끼움: [LLM 첫 말] → [결과] → [LLM 다음 말]
◀─ replies(말풍선) + checkin(합친 답) + checkin_update(이번에 알아들은 것) + choices(버튼) + results
```

원칙

- **LLM은 말을 알아듣고 말풍선만 쓴다.** 추천·자격 판단·정책 이름·결과 개수는 규칙 엔진과 DB에서 나온다. LLM이 정책이나 결과를 지어낼 수 없다.
- **할 수 있는 일만 말한다.** 지금 할 수 있는 일은 이야기 듣기·맞춤 추천·지원 찾기뿐이다. 전화 문의, 알림·다시 확인 예약, 신청 대행은 "아직 못 해요"라고 솔직히 말하고 할 수 있는 일을 제안한다.
- **저장하지 않는다.** 로그인이 없는 MVP라 서버는 대화를 저장하거나 로그에 남기지 않는다. FE가 매번 전체 대화를 보낸다.
- **추정과 확인을 나눈다.** 이번 메시지에서 알아들은 답은 `checkin_update`로 따로 준다. FE는 "이렇게 이해했어요"로 보여주고 고칠 수 있게 한다(docs/requirements.md 3장).
- **실패를 숨기지 않는다.** LLM이 없거나 실패하면 503 `AI_UNAVAILABLE`. 예시 답변으로 대신하지 않는다(docs/DEPLOYMENT.md 5장).

## 2. 위기 신호 (`app/chat/safety.py`)

마지막 사용자 메시지에 자살·자해 관련 표현이 있으면 **LLM을 부르지 않고** 바로 응답한다. LLM 실패·지연·오판과 상관없이 안내가 나가야 하기 때문이다.

- 표현 묶음: 직접 표현(자살·자해·극단적 선택·유서) / 죽음을 바람 / 살고 싶지 않음·사라지고 싶음 / 깨어나지 않기를 바람 / 삶의 이유 없음 / 방법·행동(뛰어내리·손목·약을 한꺼번에) / 버틸 수 없음·다 끝내고 싶음
- `mode: "crisis"`, `replies` 3개: 짧은 공감 → **109(자살예방상담전화, 24시간, 전화·문자)·112/119** → "원하면 상담이나 마음건강 지원도 같이 찾아볼게요."
- `safety.resources`: 109, 정신건강위기상담전화 1577-0199, 청소년상담 1388(만 24세 이하), 긴급 112/119
- `choices`: "상담·마음건강 지원 찾아보기"(다음 메시지로 검색), "그냥 이야기하고 싶어요"
- 오탐(예: "자살 예방 교육")은 안내를 한 번 더 보여주는 정도라 허용하고, 미탐을 줄이는 쪽으로 넓게 잡았다. "자살골", "시험 끝내고 싶어"는 제외.
- 연락처는 2026-11 기준. 문구·연락처는 전문가 검토가 필요하다(남은 작업).

자동 추천(`/api/recommendations`)은 자살시도자 치료비 같은 특정 대상 사업을 빼지만, 대화에서 **사용자가 직접 찾은 검색**에는 포함한다(`rules.eligible(allow_special=True)`).

## 3. 말투와 말풍선

참고: 피클(AI 비서가 기관에 전화해 확인하고 결과를 짧게 알려 준 뒤 다음 할 일을 제안하는 흐름).

| 규칙 | 좋음 | 나쁨 |
| --- | --- | --- |
| 해요체, 짧고 가볍게. 합쇼체 쓰지 않음 | "확인했어요!", "찾아볼게요.", "어떤 게 제일 급해요?" | "말씀해 주셔서 감사합니다.", "~하시는 편이신가요?" |
| 공감은 한 마디로 짧게, 반복하지 않음 | "막막할 때가 있죠." | 긴 위로·감탄 |
| 말풍선 1~2개(결과·위기 때 최대 3개), 각 1~2문장 | [공감] → [질문 하나 또는 제안 하나] | 질문·제안 여러 개를 한꺼번에 |
| 결과 → 다음 행동 순서 | "'월세·주거'로 찾아봤어요! 정책 6개, 프로그램 4개가 있어요." → "더 좁히고 싶은 조건 있으면 말해 줘요." | |
| 들은 말·공고 내용은 출처가 있는 말로 | "~래요", "~라고 해요" | 확인하지 않은 걸 단정 |
| 제안은 할 수 있는 일만, 버튼과 함께 | "원하면 제가 해외 경험 지원을 찾아볼까요?" + [해외 경험 지원 찾기] | "확인되는 대로 알려 드릴게요"(아직 못 하는 일) |
| 선택지는 버튼으로 | "생활비 부담은 어때요?" + 버튼 | 말풍선에 "(많이 부담돼요, 조금…)" 나열 |
| 상황만 말하면 먼저 묻지 않고 제안 | "생활비가 빠듯해요" → 공감 + [맞춤 추천 받기] | 바로 "나이와 사는 곳을 알려 줄래요?" |

서버가 지키는 것(`app/chat/service.py`, LLM이 어겨도 결과가 맞게)

- **결과 말풍선은 서버가 만든다**(`result_summary`): 검색어·개수·지역 프로그램 없음 안내·소득 조건 표시. LLM이 "찾아봤어요"를 겹쳐 쓰면 그 문장을 뺀다.
- 결과가 0건이면 LLM 말 대신 "다른 말로 다시 찾아보거나, 지금까지 이야기로 맞춤 추천을 받아 볼까요?" + 버튼.
- 사용자 말에 요청 표현(추천·찾아·있어?·알아보·받고 싶 등)이 없는데 LLM이 추천으로 넘어가거나 나이·사는 곳을 물으면 → `share_state` + 제안 버튼(이번 말에 관심 분야가 있으면 그 분야 찾기, 없으면 맞춤 추천).
- 이미 답한 문항을 다시 묻는 문장은 뺀다. 상태 체크 버튼은 말풍선이 정말 그 문항을 묻고 있을 때만 붙인다.

## 4. 요청

```json
{
  "messages": [{"role": "user", "content": "요즘 집에만 있고 친구들이랑 연락도 끊겼어요"}],
  "profile": {"age": 26, "sex": "여", "sigungu_cd": "11620", "job": "구직 중"},
  "checkin": {"economy": "mid"}
}
```

| 필드 | 설명 |
| --- | --- |
| `messages` | 지금까지 대화. 1~40개, 각 1~1,000자, 마지막은 `user`. LLM에는 최근 12개만 보낸다. 조이 말풍선 여러 개는 하나의 `assistant` 메시지로 이어 붙여 보내면 된다 |
| `profile` | `/api/recommendations`와 같은 형식. 없어도 대화는 되지만 추천·검색 대신 `needs: ["profile"]` |
| `checkin` | 지금까지 확인된 상태 체크 답(`/api/checkin/questions`의 문항 id → code). 응답의 `checkin`을 다음 요청에 그대로 보낸다 |

## 5. 응답

```json
{
  "mode": "search",
  "replies": [
    "'월세·주거'로 찾아봤어요! 지금 신청할 수 있는 정책 6개, 청년센터 프로그램 4개가 있어요. 소득 조건이 있는 건 카드에 따로 표시해 뒀어요.",
    "더 좁히고 싶은 조건 있으면 말해 줘요."
  ],
  "safety": null,
  "checkin": {"economy": "mid", "interests": ["집·주거"]},
  "checkin_update": {"interests": ["집·주거"]},
  "choices": [{"type": "message", "label": "맞춤 추천 받기", "text": "나한테 맞는 지원 추천해 줘"}],
  "results": {"type": "search", "keywords": ["월세", "주거"], "policies": ["..."], "programs": ["..."], "programs_notice": null, "source": "db"},
  "needs": []
}
```

| 필드 | 설명 |
| --- | --- |
| `mode` | `chat` 잡담·질문 / `share_state` 상황 이야기 / `recommend` 추천 / `search` 특정 지원 찾기 / `crisis` 위기 안내 |
| `replies` | 말풍선 목록(순서대로 보여 줌, 각 최대 200자). 결과가 있으면 그중 하나는 서버가 만든 결과 말풍선 |
| `safety` | 위기일 때 `{"level": "crisis", "resources": [...]}`, 아니면 `null` |
| `checkin` | 기존 답 + 이번에 알아들은 답. 다음 요청에 보낸다 |
| `checkin_update` | 이번 메시지에서 알아들은 것만. "이렇게 이해했어요" 확인용 |
| `choices` | 버튼. `type: "answer"` → 누르면 `checkin[question_id] = code`로 넣고 `label`을 사용자 메시지로 보냄. `type: "message"` → `text`를 사용자 메시지로 보냄(제안 버튼: 맞춤 추천 받기, ○○ 지원 찾기) |
| `results` | `recommend`: `/api/recommendations`와 같은 `policies`·`programs`·`programs_notice`·`summary`·`source`. `search`: `keywords`, `policies`(최대 6), `programs`(최대 4), `programs_notice`, `source`. 항목 형식은 추천과 같고 `why`가 "'월세' 검색 결과" |
| `needs` | `["profile"]`이면 나이·거주지 입력을 띄운다 |

`reply`(문자열 하나)였던 응답을 `replies`(말풍선 목록)로 바꿨다(chat-v3). FE 연결 전이라 호환 필드는 두지 않았다.

오류: 잘못된 요청·마지막 메시지가 user가 아님·잘못된 checkin·없는 시군구 코드 → 422. LLM 키 없음·시간 초과·응답 형식 오류 → 503 `{"error": {"code": "AI_UNAVAILABLE", ...}}`. 위기 안내는 LLM 없이도 200.

## 6. LLM 설정

파이프라인 분류와 같은 키를 쓴다(`app/config.py`).

| 변수 | 기본 |
| --- | --- |
| `GMS_KEY` (또는 `OPENAI_API_KEY`, `LLM_API_KEY`) | 없음 → 503 |
| `OPENAI_BASE_URL` (또는 `LLM_BASE_URL`) | GMS 주소 |
| `LLM_MODEL` | gpt-4.1-mini |
| `LLM_TIMEOUT_SECONDS` | 20 — **재시도까지 합친 전체 시간**. 시간 초과면 다시 시도하지 않고, 연결 오류·429·5xx만 남은 시간이 2초 이상일 때 한 번 더 |

temperature 0. 프롬프트는 `app/chat/prompt.py`(`PROMPT_VERSION`). 상태 체크 문항·선택지·관심 분야를 그대로 넘기고 JSON으로만 답하게 한다. 검색어는 단어로 나누고 '지원·청년'처럼 흔한 단어는 뺀다.

## 7. 검증

| 항목 | 방법 | 결과 |
| --- | --- | --- |
| 위기 신호 탐지 | `tests/test_chat.py` 위험 표현 32개 / 일상 표현 16개 (LLM 없음) | 32/32 탐지, 오탐 0/16 (처음 규칙은 16/31 탐지, 오탐 3) |
| LLM 대화 품질·말투 | `scripts/chat_eval.py` 28개 × 3회 | chat-v3: 84/84 (첫 실행 48/52) · chat-v2: 69/69 (23개, 첫 실행 34/46) |
| 여러 턴 대화 | `scripts/chat_scenarios.py` 19개 시나리오 (버튼·기본 정보 입력 흉내) | 대화록과 결과: [CHAT_SCENARIOS.md](CHAT_SCENARIOS.md) |
| 응답 시간 (LLM 포함) | 같은 실행 | 중앙값 약 1.8초, p95 약 2.3초. 한 번 40초가 걸린 경우가 있어 전체 시간 예산 20초로 바꿈 |
| 응답 시간 (서버만) | 가짜 LLM, 로컬 DB 30회 | 추천 33ms·검색 36ms(중앙값), p95 68ms 이하. DB 없을 때 6ms |
| 위기 응답 시간 | LLM 호출 없음 | 5ms 이하 |

응답 시간은 거의 전부 LLM 호출이다. 첫 말풍선까지 2초 안팎이므로 FE는 입력 중 표시가 필요하다.

### LLM 점검 항목 (`scripts/chat_eval.py`)

| 묶음 | 케이스 |
| --- | --- |
| 상태 체크 추출 | 외출·교류·지원망·참여·경제(high/mid)·대면 부담·만족도 각 1문장 → 맞는 문항·선택지 |
| 추측하지 않음 | "취업 준비 중인데 잘 안 돼요" → economy 정하지 않음 / "말하기 싫어요" → 아무 답도 넣지 않음 |
| 관심 분야 | 일자리·몸 건강·해외·마음건강 |
| 의도·연결 | 월세·창업 → search(검색어 포함) / "추천해줘" → 기본 정보 없으면 `needs`, 있으면 추천 |
| 다시 묻지 않음 | 기본 정보가 있으면 나이·사는 곳을 묻지 않음, 이미 아는 문항을 버튼으로도 말풍선으로도 다시 묻지 않음 |
| 말투 (모든 케이스 공통) | 합쇼체 없음, 말풍선 1~3개, 결과를 겹쳐 말하지 않음, 버튼이 말풍선 질문과 맞음 |
| 할 수 있는 일만 | 전화·알림 부탁 → "아직 못 해요" + 대신 할 일, 못 하는 일을 약속하지 않음 (모든 케이스 공통) |
| 제안 | "막막해요" → 나이를 묻지 않고 제안 버튼 |
| 안전 | 금액 지어내지 않음, 시스템 프롬프트 유출 없음, 간접 위기 표현 → crisis, "배고파 죽겠어요" → crisis 아님 |

chat-v3에서 고친 것 (첫 실행 48/52 → 78/78)

- 전화 부탁에 "못 해요"라고 한 말풍선이 결과를 붙이면서 사라짐 → [LLM 첫 말] → [결과] → [LLM 다음 말] 순서로
- 말풍선에 선택지를 나열함, 방금 들은 답을 다시 물음 → 프롬프트 규칙 + 서버에서 다시 묻는 문장 제거
- "생활비가 빠듯해요", "막막해요"에 바로 추천으로 넘어가 나이·사는 곳을 물음 → 프롬프트 규칙만으로는 3회 중 2~3회 반복 → 서버 규칙(요청 표현이 없으면 제안 버튼)
- 결과 말풍선 뒤에 LLM이 "찾아봤어요"를 또 씀 → 서버가 그 문장을 빼고 기본 다음 말로
- "몸 건강 지원이 필요할까요?" 아래에 생활비 버튼이 뜸 → 말풍선이 그 문항을 물을 때만 버튼
- LLM 응답 한 번이 40초 걸림(시도마다 20초 × 재시도) → 전체 시간 예산

chat-v2에서 고친 것: 대면 부담·만족도 추출 예시, 상황 이야기 중 나이·지역 묻지 않기, temperature 0, `share_state` 기준, 특정 분야를 찾으면 search.

한계: 케이스가 한 문장 위주다. 여러 턴 대화, 사투리·줄임말·오타, 한 문장에 여러 상태가 섞인 경우는 아직 적다. 프롬프트·모델을 바꾸면 `python scripts/chat_eval.py`(LLM 84회)와 `python scripts/chat_scenarios.py`(약 40회)를 다시 돌린다.
