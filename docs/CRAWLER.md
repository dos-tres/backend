# crawler — 청년센터 프로그램 수집

> 로컬 `ai_hackathon` 폴더에서 옮겨 온 문서다. 경로는 저장소 구조 기준으로 바꿨다 (2026-11-19). 추천 전체 흐름은 [RECOMMENDATION.md](RECOMMENDATION.md). 크롤러 코드: `pipeline/programs/crawl/`, 결과: `data/runtime/programs/`.

청년센터 홈페이지에서 프로그램과 공지 글을 모은다. 서비스 목표는 "사용자 지역의 센터 프로그램 추천"이다.
센터 목록은 온통청년 센터 API에서 가져온다. 어떤 데이터인지는 [docs/CENTER_FIELDS.md](docs/CENTER_FIELDS.md)에 정리돼 있다.

### 요청 방법

| 용도 | 요청 | 비고 |
|---|---|---|
| 목록 | `GET list.do?key=2309210005&sc_cntrSe={지점}&recordCountPerPage=48&pageIndex={n}` | 지점 필터 이름은 `cntrSe`가 아니라 **`sc_cntrSe`**다. 화면의 select 이름(`cntrSe`)으로 보내면 필터가 무시된다 |
| 목록 필터 | `sc_ctgry` (분야), `sc_aplyPrdEndYmdUseYn` (Y 상시 / N 일반), `sw` (검색어) | |
| 상세 | `POST view.do?key=2309210005`, 폼 데이터 `sprtInfoId={id}` | GET으로 보내면 내용이 없는 오류 페이지(854바이트)가 온다. 목록의 `goView('75741')`에서 id를 얻는다 |
| 정렬 | 기본 `orderBy=regYmd desc` (등록일 최신순) | 증분 수집: 이미 본 id가 나오면 멈춘다 |

목록 폼을 `POST list.do`로 그대로 보내면 "시스템 오류"가 난다. 목록은 GET으로 조회한다.

### 이용 시 주의

- 서울시 저작권 정책에 따르면, **공공누리 표시가 붙은 저작물만 허락 없이 쓸 수 있다.** 이 페이지에는 표시가 없다.
- 신청기간, 장소, 대상 같은 **사실 정보**와 원문 링크를 보여 주는 것은 문제가 적다. 반면 상세 설명 본문을 그대로 다시 게시하려면 허락이 필요할 수 있다.
- 권장: 서비스에는 **구조화된 사실 정보 + 요약 + 원문 링크 + 출처("서울청년센터")**를 표시한다. 공개 서비스로 내보내기 전에 운영 부서(서울시 미래청년기획관, 청년몽땅정보통 담당)에 이용 가능 여부를 문의한다.
- 수집 예절: 요청 간격 1초 이상, 식별 가능한 User-Agent, 하루 1회 증분 수집.

## 실행 순서

```bash
pip install -r requirements.txt
python pipeline/programs/crawl/sync_centers.py      # 1) 센터 목록 갱신 (API 한 번 호출, 몇 초)
python pipeline/programs/crawl/seoul_orang.py       # 2) 서울청년센터 17개 지점 프로그램 (증분, 약 20초)
python pipeline/programs/crawl/gnuboard.py          # 3) 그누보드 사이트 프로그램/공지 수집 (증분)
python pipeline/programs/crawl/merge.py    # 4) 두 결과를 data/runtime/programs/programs.csv 하나로 통합 (1초)
```

처음 실행할 때는 `python pipeline/programs/crawl/seoul_orang.py --full`로 목록 전체를 받는다(약 5분).

| 스크립트 | 하는 일 | 결과 |

| `seoul_orang.py` | 서울청년센터 통합 페이지 → 지점별 프로그램 수집 | `data/runtime/programs/seoul_orang/programs.csv` |

## 센터 목록을 주기적으로 갱신해야 하나? → 그렇다. 크롤링 전에 매번

- 센터 API 응답은 요청 한 번(약 250건)이라 부담이 거의 없다. 크롤러를 돌리기 전에 `sync_centers.py`를 먼저 돌리면 된다.
- 바뀌는 것: 센터가 새로 생기거나 문을 닫고, **홈페이지 주소가 바뀐다.** 홈페이지가 바뀌면 크롤 대상이 바뀐다.
- 기록 방식:
  - `centers.csv`는 **삭제된 센터도 지우지 않고** `status=removed`로 남긴다. 이미 수집한 글이 가리키는 센터 번호(`cntrSn`)가 끊기지 않게 하기 위해서다.
  - 추가(added), 삭제(removed), 다시 나타남(reappeared), 필드 변경(modified)을 `centers_changes.csv`에 계속 추가한다.
- 안전장치: 받은 센터 수가 기존 활성 센터의 80% 미만이면 **갱신하지 않고 중단한다.** API가 일시적으로 이상하게 응답해서 센터를 대량으로 "삭제" 처리하는 일을 막기 위해서다.
- 홈페이지 주소가 바뀌었다는 기록(`modified … cntrUrlAddr`)이 생기면 `python pipeline/programs/crawl/gnuboard.py --redetect`로 다시 감지한다.

권장 주기: 프로그램 공지는 자주 올라오므로 **수집은 하루 1회**, 센터 목록 동기화도 그 직전에 같이 한다. Windows 작업 스케줄러 예:

```
schtasks /create /tn youth-crawl /sc daily /st 06:00 ^
  /tr "cmd /c cd /d C:\...\crawler && python pipeline/programs/crawl/sync_centers.py && python pipeline/programs/crawl/seoul_orang.py && python pipeline/programs/crawl/gnuboard.py"
```

## seoul_orang.py — 서울청년센터 프로그램

### 동작

1. **목록** — 지점별로 `GET list.do?sc_cntrSe={지점}`, 한 페이지에 48건씩, 등록 최신순.
   - 목록에서 상태, 분야, 제목, 신청기간, 진행일정, 장소, 대표 이미지를 저장한다. **지난 글도 모두 저장한다.**
   - 증분: 한 페이지가 모두 이미 본 글이면 그 지점은 멈춘다. 다시 본 글은 상태(모집중→마감)와 `last_seen`을 갱신한다.
2. **상세** — `POST view.do`, 대상 글만 받는다.
   - 대상: 상태가 "마감"이 아니고, 신청 마감일이 지나지 않았거나, 상시 모집이면서 진행일정이 끝나지 않은 글
   - 받는 정보: 대상, 담당기관, 주소, 본문, 본문 속 링크
   - 지난 글 4,600여 건은 목록 정보만으로 충분해서 상세를 받지 않는다(받으면 1시간 넘게 걸린다).
3. **지역 연결** — 지점 코드의 자치구로 `data/runtime/programs/centers.csv`에서 같은 구의 "서울청년센터"를 찾아 `cntrSn`과 지역코드를 붙인다.


## gnuboard.py

### 동작

1. **감지** (`--redetect`일 때, 또는 처음 실행할 때)
   - 활성 센터의 홈페이지에서 `…/bbs/board.php?bo_table=…` 링크를 찾는다.
   - 플랫폼 라벨을 믿지 않고 링크를 직접 본다. 그래서 다른 플랫폼으로 분류됐던 그누보드 사이트도 잡힌다.
   - 홈페이지와 **같은 호스트**의 게시판만 인정한다. 외부 업체 게시판 링크는 제외한다.
   - 한 사이트를 여러 센터가 쓰면(천안 3곳) 사이트 단위로 한 번만 수집하고, 글에 센터를 모두 연결한다.
   - 게시판 이름은 메뉴 링크 글자에서 가져온다. 메뉴에 없으면 목록 페이지 제목에서 가져온다. 이름에 따라 게시판을 분류한다.

   | 분류 | 기준 (이름 또는 bo_table) | 수집 |
   |---|---|---|
   | program | 프로그램, 모집, 신청, 교육, 강좌, 행사, 참여, 사업, 역량강화, 창업지원, 동아리… | ✅ |
   | notice | 공지, 알림, 소식, 뉴스 | ✅ |
   | other | 위에 해당하지 않음 (청년정책, 취업정보 등 외부 정보 재게시) | `--all-boards`일 때만 |
   | skip | 갤러리, 자료실, FAQ, **상담, 문의, 자유게시판**, 대관, 후기, 채용, 언론보도… | ❌ |

2. **수집**
   - 게시판 목록에서는 **글 번호(`wr_id`)만** 믿는다. 스킨마다 목록 HTML이 달라서다(링크 글자가 "모집 중"인 경우도 있다).
   - 처음 보는 글만 상세 페이지를 받아 제목, 작성일, 본문, 이미지, 첨부파일 이름을 추출한다.
     - 제목: 그누보드 기본 선택자 → 목록 링크 글자 → `<title>`
     - 작성일: "작성일/등록일" 표시가 붙은 날짜 → 날짜 영역 → 제목 바로 뒤의 날짜 → 목록 행의 날짜. 모집기간 날짜는 작성일로 쓰지 않는다.
     - 본문: `#bo_v_con` 등 → 없으면 텍스트가 몰린 영역을 추정
   - 목록 한 페이지가 모두 이미 본 글이면 그 게시판은 거기서 멈춘다(증분 수집).
   - 짧은 주소(`/main_program/123`)와 하위 경로 설치(`/gnbd/bbs/`)도 처리한다.

### 수집하지 않는 것 (의도적으로)

| 대상 | 처리 |
|---|---|
| robots.txt가 막은 사이트 | 수집하지 않는다. `detect_log.csv`에 `robots_blocked`로 남긴다 |
| 상담·문의·자유게시판 | 개인정보와 스팸이 섞여 있다(천안 "개인상담" 게시판은 스팸 광고로 가득했다). 게시판을 통째로 제외한다 |
| 비밀글 | 저장하지 않는다 |
| 회원 전용 글 | 로그인하지 않는다. 목록의 제목과 행 텍스트만 저장하고 `note=login_required`로 표시한다 |
| 담당자 개인 이름 등 | 별도로 추출하지 않는다 |

예의: robots.txt를 지키고, 호스트당 요청 간격을 1초 이상 두고, 식별 가능한 User-Agent를 쓴다(`youth-program-crawler`).

### 옵션

```
--redetect          센터 홈페이지를 다시 훑어 사이트·게시판 재감지
--detect-only       감지만
--pages N           게시판당 목록 최대 N페이지 (기본 2)
--max-new N         게시판당 상세를 받을 새 글 최대 수 (기본 30)
                    · 목록에서 찾은 새 글이 N개를 넘으면 최신 N개만 받는다. 나머지는 다음 실행 때 채워진다
                      (첫 실행 뒤 두 번째 실행에서 117건이 추가되고, 세 번째 실행에서 0건이 됐다)
                    · 과거 글까지 깊게 모으려면: --pages 10 --max-new 300
--all-boards        other 게시판까지 수집
--site 부분문자열    특정 사이트만
```

| 문제 | 원인 | 조치 |

| 사하구 센터가 외부 업체 게시판에 연결됨 | 구청 사이트에 있는 외부 그누보드 링크를 그대로 채택 | 홈페이지와 같은 호스트의 게시판만 인정 |
| 제주 게시판 4개가 이름 없이 `other`로 빠짐 | 홈페이지에 최근 글 링크만 있고 메뉴 링크가 없음 | 이름 없는 게시판은 목록 페이지 제목에서 이름 추출 |
| 천안 "개인상담" 게시판이 스팸 광고로 가득 | 이용자가 쓰는 게시판인데 "신청"이라는 단어로 program 분류됨 | 상담·문의를 skip 분류에 추가 |
| 제천 "상담신청" 글이 비밀글 | 〃 | skip 분류 + 비밀글은 저장 안 함 |
| 천안 "프로그램" 글 제목이 "모집기간 : …", 본문 빈 값 | 회원 전용 글 | 로그인하지 않는다. 목록 정보만 저장하고 `note=login_required` 표시. 제목 후보에서 "모집기간 :"으로 시작하는 글자 제외 |
| 안산 글 작성일에 모집 시작일이 들어감 | 날짜 영역 선택자가 모집기간을 먼저 잡음 | "작성일/등록일" 표시가 붙은 날짜를 우선 사용 |
| 작성일이 미래(진행일)인 글 9건 | 제목 근처 날짜를 작성일로 씀 | 수집일보다 뒤인 날짜는 작성일로 쓰지 않음 |
| 전북청년허브 목록 실패 | 정상 페이지를 HTTP 500 상태로 보냄 | 5xx여도 본문이 충분하면 받아들임 |
