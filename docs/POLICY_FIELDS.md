# 청년정책 API (getPlcy) 필드 정의

> 로컬 `ai_hackathon` 폴더에서 옮겨 온 문서다. 경로는 저장소 구조 기준으로 바꿨다 (2026-11-19). 추천 전체 흐름은 [RECOMMENDATION.md](RECOMMENDATION.md).

온통청년 `getPlcy` 응답의 필드 정의다. 코드값은 실제 데이터 예시로 구조를 풀어 설명한다.
수치는 2026-11-18에 수집한 4,016건 기준이다. 센터 API는 [CENTER_FIELDS.md](CENTER_FIELDS.md)를 본다.

## 요청과 응답

```
GET https://www.youthcenter.go.kr/go/ythip/getPlcy
    ?apiKeyNm=<정책 API 키>&pageNum=1&pageSize=100&rtnType=json[&zipCd=11000]
```

```json
{
  "resultCode": 200,
  "resultMessage": "성공적으로 데이터를 가지고 왔습니다.",
  "result": {
    "pagging": { "totCount": 4016, "pageNum": 1, "pageSize": 100 },
    "youthPolicyList": [ { "plcyNo": "20261113005400214853", ... } ]
  }
}
```

- 페이지 정보 키는 `pagging`이다(원문 철자 그대로). `totCount` 4,016건을 모두 받았고 `plcyNo`도 모두 고유하다.
- **모든 값은 문자열로 온다.** 나이, 금액, 건수도 `"0"`, `"5000"`처럼 온다.
- 값이 여러 개인 필드는 **쉼표로 구분한 문자열**이다(`"0013003,0013006"`).
- 간헐적으로 HTTP 400/500이 나지만 다시 요청하면 성공한다.

## 코드 구조 읽는 법

### 1. 공통코드 7자리 — `00` + 그룹(2) + 순번(3)

대부분의 코드 필드가 같은 규칙을 따른다.

```
0042006
││ │└┴┴─ 006  : 그룹 안의 순번 → "보조금"
││ └──── 42   : 코드 그룹 → 정책 제공방법
└┴────── 00   : 고정 접두어
```

| 그룹 | 필드 | 의미 |
|---|---|---|
| 0011 | `plcyMajorCd` | 전공 |
| 0013 | `jobCd` | 취업상태 |
| 0014 | `sbizCd` | 특화분야 |
| 0042 | `plcyPvsnMthdCd` | 정책 제공방법 |
| 0043 | `earnCndSeCd` | 소득조건 |
| 0044 | `plcyAprvSttsCd` | 승인상태 |
| 0049 | `schoolCd` | 학력 |
| 0054 | `pvsnInstGroupCd` | 제공기관 그룹 |
| 0055 | `mrgSttsCd` | 결혼상태 |
| 0056 | `bizPrdSeCd` | 사업기간 구분 |
| 0057 | `aplyPrdSeCd` | 신청기간 구분 |

**그룹마다 보통 마지막 번호가 "제한없음"이다.** 예: `0011009`, `0013010`, `0049010`, `0014010`.
자격 필터를 적용할 때는 "제한없음 코드가 들어 있으면 통과"로 처리하면 된다.

```
jobCd = "0013003,0013006"   → 미취업자 또는 (예비)창업자만 신청 가능
jobCd = "0013010"           → 취업상태 제한 없음
```

### 2. 정책번호 `plcyNo` 20자리 — 등록일(8) + 제공기관그룹(7) + 일련번호(5)

```
20261113 0054002 14853
│        │       └─ 14853   : 전체 일련번호 (1 ~ 14853, 계속 증가)
│        └───────── 0054002 : 등록 당시 제공기관 그룹 (0054001 중앙부처 / 0054002 지자체)
└────────────────── 20261113: 등록일 YYYYMMDD
```

- 중간 7자리가 `pvsnInstGroupCd`와 같은 경우는 3,961건이다. 나머지 55건은 등록한 뒤 그룹이 바뀐 것이다(예: `...0054001 13858`인데 필드값은 `0054002`).
- 앞 8자리가 `frstRegDt`의 날짜와 같은 경우는 3,945건이다.
- → **`plcyNo`는 식별자로만 쓰고, 번호를 잘라서 정보를 꺼내 쓰지 말 것.** 그룹이나 날짜가 필요하면 해당 필드를 쓴다.

### 3. 지역코드 `zipCd` 5자리 — 시도(2) + 시군구(3)

`zipCd`는 **법정동코드(10자리)의 앞 5자리**, 즉 시군구 코드다. 정책 하나에 여러 개가 쉼표로 이어져 있다.

```
법정동코드  41 113 101 00   (경기도 수원시 권선구 세류동)
            │  │   │   └─ 리 (2)
            │  │   └───── 읍면동 (3)
            │  └───────── 시군구 (3)  ─┐
            └──────────── 시도 (2)    ─┴─ zipCd = 41113
```

**시도 코드 (앞 2자리)** — 실제 데이터에 나오는 16개

| 코드 | 시도 | 코드 | 시도 |
|---|---|---|---|
| 11 | 서울특별시 | 36 | 세종특별자치시 |
| 12 | 전남광주통합특별시 | 41 | 경기도 |
| 26 | 부산광역시 | 43 | 충청북도 |
| 27 | 대구광역시 | 44 | 충청남도 |
| 28 | 인천광역시 | 47 | 경상북도 |
| 30 | 대전광역시 | 48 | 경상남도 |
| 31 | 울산광역시 | 50 | 제주특별자치도 |
| | | 51 | 강원특별자치도 |
| | | 52 | 전북특별자치도 |

> 옛 광주(29)와 전남(46) 코드는 `zipCd`에 **나오지 않는다.** 모두 `12`(전남광주통합특별시)로 바뀌었다.
> 반면 기관코드에는 `6290000 광주광역시`, `6460000 전라남도`가 아직 남아 있다(아래 4번 참고).

**시군구 코드 (뒤 3자리)** — 일반구가 있는 시는 끝자리로 시와 구를 나눈다

```
41110  수원시 (시 단위 코드, 끝자리 0)
41111  수원시 장안구  ┐
41113  수원시 권선구  │ 앞 4자리 4111이 같음 → 같은 수원시
41115  수원시 팔달구  │
41117  수원시 영통구  ┘
41150  의정부시 (일반구 없음)
```

- 실제 데이터에는 `41111, 41113, 41115, 41117`만 있고 `41110`은 없다. 이처럼 **일반구가 있는 시는 구 코드로만** 들어간다.
- 같은 시를 찾으려면 앞 4자리로 묶는다(`41461/41463/41465` → 용인시).
- 시도 단위로 찾으려면 앞 2자리로 묶는다.

**정책의 지역 범위는 `zipCd`에 들어 있는 코드 개수로 판단한다**

| 범위 | 판단 기준 | 건수 | 예시 |
|---|---|---|---|
| 전국 | 코드 240개 이상 | 698 | 중앙부처 정책 대부분 |
| 시도 전체 | 한 시도의 시군구가 모두 들어 있음 | 1,548 | `41111,41113,...,41830` (경기 48개) |
| 시군구 여러 개 | 한 시도 안에서 일부만 | 636 | |
| 시군구 1개 | 코드 1개 | 1,106 | `11260` (서울 중랑구) |
| 여러 시도 | 시도 2개 이상이지만 전국은 아님 | 28 | 초기창업패키지 `12,50,52` |

**"전국"을 나타내는 전용 코드는 없다.** 전국 정책은 시군구 코드를 모두 나열하는데, 개수가 등록 시점마다 다르다.

```
256개 (304건) ─ 최신 목록
254개  (69건) ─ 인천 28155, 28275 없음 (인천 행정구역 개편 전)
251개 (316건) ─ 울산 5개 구군(31110,31140,31170,31200,31710)이 통째로 빠짐 ⚠
```

→ 코드 개수가 정확히 256인지가 아니라 **"240개 이상이면 전국"**으로 판단해야 한다.
그러지 않으면 울산 사용자에게 전국 정책 316건이 누락된다.

행정구역이 개편되면서 옛 코드와 새 코드가 섞여 있다. 시 단위 코드와 구 단위 코드가 섞인 경우도 있다.

| 옛 코드 / 시 단위 | 새 코드 / 구 단위 | 건수 (옛 → 새) | 비고 |
|---|---|---|---|
| `28110` 중구, `28140` 동구, `28260` 서구 | `28125` 제물포구, `28155` 영종구, `28275` 서해구 | 2·4·2 → 869·329·333 | 인천 행정구역 개편 |
| `41590` 화성시 | `41591, 41593, 41595, 41597` (병점구 등) | 345 → 472 | 화성시에 일반구가 생김 |
| `44130` 천안시 | `44131` 동남구, `44133` 서북구 | 135 → 827 | 시 단위 코드가 섞여 들어감 |
| `30000` | — | 1 | 비정상 값 |

→ 사용자 코드를 매칭할 때는 **옛 코드와 시 단위 코드(앞 4자리 + `0`)도 함께 조회**해야 한다.
예: 화성시 병점구(`41595`) 사용자 → `41595`, `41590` 둘 다 조회한다.

### 4. 기관코드 7자리 — 첫 글자가 기관 유형

`sprvsnInstCd`, `operInstCd`, `rgtrInstCd`, `rgtrUpInstCd`, `rgtrHghrkInstCd`가 이 규칙을 따른다(행정표준기관코드).

| 첫 글자 | 유형 | 실제 예시 |
|---|---|---|
| `1` | 중앙행정기관 | `1613000` 국토교통부, `1352000` 보건복지부, `1492000` 고용노동부 |
| `6` | 광역자치단체 | `6110000` 서울, `6260000` 부산, `6410000` 경기, `6470000` 경북, `6130000` 전남광주통합 |
| `3` | 광역시 소속 구·군 | `3340000` 부산 사하구, `3450000` 대구 북구 |
| `4`, `5` | 도 소속 시·군 | `5710000` 충북 청주시, `5890000` 영광군, `4530246` (부서) |
| `B` | 공공기관 | `B552644` 한국콘텐츠진흥원, `B554315` 경기주택도시공사 |
| `C`, `D`, `7` | 대학, 기관 내부 조직 등 | `7002118` 인하대학교, `D311086` 한국장학재단 |
| 공백 7칸 / `0000000` | 값 없음 | 이름 필드에만 값이 있는 경우가 있다 |

```
6470000   경상북도 (본청)          ← 뒤 4자리가 0000이면 기관 자체
5895000   장성군
5895004   장성군 인구경제실       ← 뒤자리가 0이 아니면 하위 부서
```

- 광역자치단체 코드는 `6` + 시도코드(2) + `0000` 구조다. 대부분 `zipCd`의 시도 코드와 같지만 **다른 곳이 있다.**

  | 시도 | 기관코드 | zipCd 시도 코드 | 같은가 |
  |---|---|---|---|
  | 서울·부산·대구·인천·대전·울산·경기·충북·충남·경북·경남·제주 | `6110000` ~ `6500000` | 11 ~ 50 | ✅ 같다 |
  | 강원특별자치도 | `6530000` | 51 | ❌ (특별자치도 전환 전 코드 53) |
  | 전북특별자치도 | `6540000` | 52 | ❌ (특별자치도 전환 전 코드 54) |
  | 전남광주통합특별시 | `6130000` | 12 | ❌ |
  | 옛 광주광역시 / 전라남도 | `6290000` / `6460000` | 없음 → 12 | 아직 남아 있다(이름이 `광주시청`인 경우도 있음) |
  | 세종특별자치시 | `5690000` | 36 | ❌ (6으로 시작하지 않음) |

  → 기관코드로 지역을 판단하려면 위 표로 매핑해야 한다. **지역 판단은 `zipCd`를 쓰는 게 낫다.**
- `rgtrHghrkInstCdNm`(최상위 등록기관 이름)은 17%가 비어 있다. 코드만 있는 경우가 있다(`6440000` + 빈 이름 = 충청남도).

### 5. 청년정책 기본계획 번호 — 차수 > 정책방향 > 중점과제 > 과제

```
bscPlanCycl=2  bscPlanPlcyWayNo=004  bscPlanFcsAsmtNo=012  bscPlanAsmtNo=044
     │                │                     │                    └─ 과제
     │                │                     └─ 중점과제 (정책방향마다 4개씩)
     │                └─ 정책방향 001~005
     └─ 기본계획 차수 (1차 1,445건 / 2차 2,571건)
```

- 중점과제 번호는 정책방향에 묶여 있다. 예: 정책방향 `001`의 중점과제는 `001~004`, `002`의 중점과제는 `005~008`.
- 과제 번호(`bscPlanAsmtNo`)는 여러 중점과제에서 다시 쓰인다. 고유 키로 쓰려면 네 값을 모두 묶어야 한다.
- 각 번호가 뜻하는 이름은 API에 없다. 필요하면 청년정책 기본계획 문서에서 가져와야 한다.

### 6. 분류 `lclsfNm` / `mclsfNm` — 쉼표 위치로 짝을 맞춘다

```
lclsfNm = "교육･직업훈련,교육･직업훈련"
mclsfNm = "온·오프라인교육 ,미래역량강화"
         → (교육･직업훈련 > 온·오프라인교육), (교육･직업훈련 > 미래역량강화)
```

- 분류가 1개인 정책은 3,879건이고, 2개 이상인 정책은 136건이다. 쉼표로 나눈 개수는 두 필드가 항상 같다.
- 값 뒤에 공백이 붙어 있을 수 있다(`"온·오프라인교육 "`). → `strip()`이 필요하다.
- **2025년에 등록된 정책(697건)은 옛 대분류 체계를 쓴다.** 그 외에는 모두 새 체계다.

| 옛 대분류 (2025 등록분) | → 새 대분류 |
|---|---|
| 교육 | 교육･직업훈련 |
| 복지문화 | 금융･복지･문화 |
| 참여권리 | 참여･기반 |
| 일자리, 주거 | 그대로 |

| 옛 중분류 | → 새 중분류 |
|---|---|
| 온라인교육 | 온·오프라인교육 |
| 문화활동 | 문화활동 및 생활지원 |
| (참여권리) 권익보호 | (일자리) 권익보호 와 이름이 같다. 대분류와 함께 봐야 한다 |

- 대분류 안의 `･`(U+FF65)는 일반 가운뎃점 `·`(U+00B7)과 **다른 문자다.** 중분류 `온·오프라인교육`에는 `·`가 쓰인다. 문자열로 비교할 때 주의한다.

### 7. 기간 — `aplyYmd` 문자열

```
"20261102 ~ 20261211"                              ← 1,949건, 기본 형식
"20260101 ~ 20261231\N20270101 ~ 20271231"         ← 기간이 여러 개면 리터럴 \N 으로 구분
"         ~         "                              ← 공백만 있는 값 (1건)
""                                                 ← 상시·마감 정책
```

- `aplyPrdSeCd`와 함께 해석한다. `0057001`(특정기간)이면 `aplyYmd`가 있고, `0057002`(상시)와 `0057003`(마감)이면 비어 있다.
- 파싱: `\N`으로 나눈 다음 ` ~ `로 나눈다.
- `bizPrdBgngYmd`/`bizPrdEndYmd`는 `YYYYMMDD`다. 비어 있을 때 빈 문자열이 아니라 **공백 8칸**으로 올 수 있다(1,360건).

### 8. 소득 금액 — 단위가 섞여 있다

```
earnCndSeCd=0043002(연소득)  earnMinAmt="0"     earnMaxAmt="5000"     → 연 5,000만 원 이하
earnCndSeCd=0043002          earnMinAmt="2580"  earnMaxAmt="5532"     → 연 2,580~5,532만 원
earnCndSeCd=0043002          earnMinAmt="0"     earnMaxAmt="43056240" → 원 단위로 입력한 것 (약 4,306만 원)

```

- 기본 단위는 **만원**이다. 100,000을 넘는 값은 원 단위로 보고 10,000으로 나눈다.
- `0043003`(기타)일 때는 금액 필드를 믿지 말고 `earnEtcCn` 서술을 본다.

### 9. 나이 — `0`은 제한 없음

| `sprtTrgtAgeLmtYn` | min | max | 건수 | 해석 |
|---|---|---|---|---|
| Y | 0 | 0 | 1,039 | 나이 제한 없음 |
| N | 19 | 39 | 810 | 19~39세 |
| Y | 19 | 39 | 323 | 19~39세 |

## 지역 매칭에 쓸 때

**`zipCd`는 사업을 운영하는 지역이 아니라 신청자의 거주지 요건이다.**
예를 들어 대구시 "귀환 청년 주거지원"은 대구 사업이지만 `zipCd`에 전국이 들어 있다. 다른 지역 청년이 대구로 오도록 하는 사업이라서다. 이렇게 지자체가 등록했는데 `zipCd`가 전국인 정책이 175건이다.

사용자의 시군구 코드 `U`(5자리)로 정책을 찾는 규칙:

```python
codes = set(zipCd.split(","))
if U in codes or 옛코드(U) & codes:        # 1) 직접 포함 (개편 전 코드 포함)
    if len(codes) >= 240:  scope = "전국"
    elif len(codes) == 1:   scope = "우리 시군구"
    else:                   scope = "우리 시도" or "인근"
```

추천 순위는 `우리 시군구 > 우리 시도 > 전국`으로 매긴다. 전국 정책이 698건이나 되므로 그대로 섞으면 지역 정책이 묻힌다.

자세한 설계는 [README.md의 지역 매칭 설계](README.md#지역-매칭-설계)를 본다.
