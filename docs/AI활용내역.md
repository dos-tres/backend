# AI 활용내역

둘셋은 서비스 안에서 사용하는 AI와 개발을 돕는 AI를 구분해 활용했다. OpenAI API로 사용자 입력 분석과 공고 정보 처리를 구현했고, Claude Code와 Codex, ChatGPT로 데이터 수집, 기능 개발, 연동 테스트를 진행했다. 서비스의 기능 범위와 추천 기준은 팀이 결정하고 AI가 생성한 코드는 직접 검증해 반영했다.

### ① 활용 AI 모델·도구

[서비스] OpenAI GPT-4.1 mini API: 사용자 상황과 관심 분야 파악, 검색어 변환, 공고 정보 추출 및 분류, 공고 내용에 대한 질의응답, 신청 문항 초안 작성

[백엔드] Claude Code(Claude Opus 5.5): 서버와 데이터 수집 파이프라인 코드 작성, 리팩터링, 오류 수정, 자동 테스트 작성

[프론트엔드] Codex 및 Codex CLI: React와 TypeScript 기능 구현, 백엔드 API 연동, 화면 상태 처리, 빌드 오류 수정

[디자인] ChatGPT(이미지 생성, AI 생성): 챗봇 캐릭터 '조이' 이미지 생성

[디자인] Figma: 둘셋 로고 제작

[개발 검증 및 문서] ChatGPT, Claude Code: 기능 요구사항 정리, API 응답과 오류 로그 분석, 통합 테스트 절차 작성, 구현 내용과 소개서 대조

### ② AI 활용 범위와 팀의 기여

서비스 기능: OpenAI API를 이용해 사용자가 입력한 문장에서 현재 상태, 관심 분야, 요청을 추출하고 정책 검색에 필요한 조건과 검색어로 변환했다. 선택한 공고에 대한 질문에는 공고 원문을 근거로 답하고 신청 문항의 초안을 작성하도록 했다. 지원 자격과 추천 순서는 AI가 판단하지 않는다. 팀이 연령, 거주지, 취업 상태, 학력, 마감 여부를 비교하고 생활 점검과 관심 분야별 가중치를 적용하는 규칙을 설계했다. 결과 개수와 이름이 들어가는 결과 안내 문장은 실제 검색 결과를 바탕으로 서버가 생성한다. 신청서 제출은 사용자가 직접 선택한다.

데이터 처리: 온통청년 API 수집과 청년센터 게시판 크롤링, 매일 새벽 갱신하는 파이프라인을 팀이 설계하고 Claude Code로 구현을 보조했다. 형식이 다른 공고에서 AI로 대상, 장소, 일정, 신청 기간, 준비물 등을 추출하고 지원 영역을 분류했다. 항목별 원문 근거를 확인해 저장하며, 분류가 불확실한 공고는 추천에서 보류한다. 갱신 실패 시에는 이전 데이터를 유지한다.

프론트엔드 개발: 사용자 정보 입력과 수정, 시도, 시군구, 동의 단계별 지역 선택, 생활 점검, 자가진단, 맞춤 추천 결과, 정책 및 프로그램 상세 조회 화면을 Codex로 구현했다. 백엔드 API 명세와 실제 응답을 대조해 요청 값과 화면의 데이터 처리 방식을 수정했고, 사용자 조건을 저장한 뒤 점검 결과와 추천 공고를 확인할 수 있도록 화면 흐름을 연결했다. 화면만 구현하는 데 그치지 않고 정보 변경 후 재조회, 점검 결과 표시, 추천 상세 이동까지 실제 서버와 연동해 점검했다.

개발 협업과 오류 해결: Codex와 ChatGPT에 빌드 오류, HTTP 응답, 터미널 로그를 제공해 원인을 분석하고 수정안을 만들었다. 특히 API 요청 주소와 필드 불일치, 화면 표시와 실제 저장 결과의 차이를 확인해 연동 코드를 보완했다. Git 브랜치와 PR의 변경 내용을 검토하고 병합 전 빌드도 확인했다. 기능 요구사항, API 규격, 최종 수정과 병합 여부는 팀이 판단했다.

프롬프트: 팀이 AI 비서의 역할과 응답 형식, 확인되지 않은 정책이나 자격을 만들어내지 않는 규칙을 정했다. 온도를 0으로 설정하고, 사용자가 상황을 설명했을 때 불필요하게 개인정보부터 묻는 사례 등을 점검해 프롬프트와 서버 후처리를 개선했다.

### ③ API·외부 데이터·오픈소스

API: 온통청년 청년정책 API(정책 수집), OpenAI API(서비스 AI), 카카오맵 API(센터 위치), Google Forms(시연용 신청서)

외부 데이터: 서울청년센터 오랑 및 지역 청년센터 게시판 공고, 법정동코드(지역 선택, 2026년 11월 20일 기준)

오픈소스: FastAPI, SQLAlchemy, Alembic, uvicorn, requests, BeautifulSoup, psycopg, pydantic-settings(백엔드), React, Vite, TypeScript, lucide-react(프론트엔드)

상세 출처와 라이선스는 소개서 별첨에 기재했다.

### ④ 검증 및 한계 대응

코드 검증: AI가 만든 코드를 직접 실행하고 자동 테스트 148개로 추천 규칙, 자격 판단, API, DB 적재를 검증했다. 대화 평가 84건으로 요청 파악과 결과 안내를 점검했다. 프론트엔드는 실제 서버와 연결해 정보 저장, 지역 선택, 생활 점검, 자가진단, 추천 조회와 상세 화면을 확인했다. 오류는 응답 코드와 로그를 분석해 수정하고 같은 흐름을 다시 실행했다.

추천 품질: 가상 사용자 사례에서 선택한 관심 분야의 추천이 누락되는 문제를 찾아 분야별 최소 한 개가 보이도록 규칙을 보완했다. 이전 행정구역 코드로 후보가 누락되는 문제도 테스트에 반영했다.

데이터 검증: 현재 정책 2,335개와 프로그램 137개를 제공한다. 프로그램 137개 중 127개는 AI 추출 항목의 원문 근거를 확인했고 나머지는 수집한 원문 정보를 표시한다. 마감된 공고가 추천에 포함되지 않도록 점검했다.

환각 및 안전: 서버가 검증한 데이터 안에서만 답변하고 공식 공고 링크를 제공한다. 불명확한 자격 조건은 추가 확인을 안내한다. AI 호출은 20초 제한과 1회 재시도를 적용하고 실패 시 임의의 답변을 생성하지 않는다. 자살 및 자해 표현은 별도 규칙으로 감지해 109 등 상담 연락처를 우선 안내한다.

개인정보와 한계: 로그인 없이 이용하며 설문과 대화는 서버에 저장하지 않는다. 신청 초안에 포함된 이름과 연락처는 자리표시자로 바꿔 전달하고, 시연에는 가상 데이터를 사용한다. API 키는 환경변수로 관리한다. 소득 조건은 자동 판정하지 않으며 청년센터 수집은 서울 중심이다. 신청 대행은 시연용 신청서에 한정한다. 데이터 갱신 시점 표시와 자유 입력 개인정보 마스킹은 향후 보완할 예정이다.
