# AI 활용내역

**① 활용 AI 모델·도구**
- [서비스] OpenAI GPT-4.1 mini API: 대화 이해(상태·관심 분야·요청 정리, 검색어 변환), 선택한 공고에 대한 질문 답변, 청년센터 공고 정보 추출·지원 영역 분류, 신청 문항 초안 작성
- [개발·백엔드] Claude Code(Claude Opus 5.5): 서버·데이터 수집 파이프라인 코드 초안, 리팩터링·디버깅, 테스트 작성, 문서와 실제 구현 대조
- [개발·프론트엔드] Codex: 화면 코드 초안 생성, API 연동 코드 작성, 수정·디버깅
- [문서] Claude Code: 소개서·AI 활용내역 초안 작성, 문서 내용과 실제 코드 대조 검토
- [디자인] Figma: 화면 구성과 디자인 시안 제작

**② AI 활용 범위와 팀의 기여**
- 서비스 기능: AI는 사용자의 자유 입력을 상태·관심 분야·요청·검색어로 구조화하고, 공고 원문을 근거로 질문에 답하며, 신청 문항 초안을 작성함. 자격 판단과 추천 순서·추천 이유는 AI를 쓰지 않고 팀이 설계한 규칙으로 계산함(연령·거주지·취업 상태·학력·마감 여부 비교, 상태 체크·관심 분야·거주 지역 기반 점수). 같은 입력이면 항상 같은 결과가 나오며, 결과 개수·이름이 들어가는 안내 문장도 AI가 아닌 서버가 실제 결과로 만듦. 대화 한 턴은 위기 표현 확인(규칙) → 입력 구조화(AI) → 후보 검색·정렬(규칙) → 결과 안내(서버) 순서로 처리하며, 신청서는 사용자가 직접 [제출하기]를 눌렀을 때만 제출함.
- 데이터: 온통청년 API 수집, 청년센터 게시판 크롤러, 매일 새벽 갱신하는 파이프라인은 팀이 설계함. AI는 형식이 제각각인 공고 본문에서 대상·일정·장소·신청 기간·준비물을 추출하고, 정책과 같은 기준으로 지원 영역을 분류함. 분류 확신도가 낮은 공고는 추천에서 보류하고, 갱신이 실패하면 전날 데이터를 유지함.
- 프롬프트: 조이의 역할, 말투, 출력 형식, 금지 규칙(정책 이름·소득·자격 지어내기, 할 수 없는 일 약속하기)은 팀이 설계함. 응답이 매번 달라지지 않도록 온도를 0으로 두고, 점검에서 나온 문제는 규칙으로 보완함. 예를 들어 사용자가 상황만 말했는데 AI가 곧바로 나이·사는 곳을 묻는 경우를 찾아, 서버가 이를 "찾아볼까요?" 제안 버튼으로 바꾸도록 고침.
- 개발: 코드 초안과 리팩터링은 AI가 생성하고, 팀이 요구사항·API 계약·DB 구조·화면 흐름을 정한 뒤 코드를 검토·수정·통합함. 문제 정의, 상태 체크 문항, 추천 가중치와 그 근거는 팀이 직접 정하고 기록함. 화면은 팀이 Figma로 흐름과 캐릭터 기준을 정한 뒤, Codex가 만든 초안을 그 기준에 맞게 고침.

**③ API·외부 데이터·오픈소스**
- API: 온통청년 청년정책 API(정책 수집), OpenAI API(서비스 AI), 카카오맵 API(센터 위치), Google Forms(시연용 신청서)
- 외부 데이터: 서울청년센터 오랑 및 지역 청년센터 게시판 공고(프로그램 수집), 법정동코드(지역 선택, 2026-11-20 기준)
- 오픈소스: FastAPI, SQLAlchemy, Alembic, uvicorn, requests, BeautifulSoup, psycopg, pydantic-settings(백엔드), React, Vite, TypeScript, lucide-react(프론트엔드)
- 상세 출처·링크·라이선스는 소개서 지정 별첨의 「활용한 외부 자원·출처」 표에 기재함.

**④ 검증 및 한계 대응**
- 코드 검증: AI가 만든 코드는 직접 실행하고, 자동 테스트 148개로 추천 규칙·자격 판단·API·DB 적재를 검증함. 대화 평가 시나리오 84건으로 요청 파악, 같은 질문 반복, 결과 안내를 점검하고 프롬프트와 후처리 규칙을 고침. 화면은 실제 서버 응답과 대조해 확인하고 검증 기록을 남김.
- 추천 품질 점검: 가상 사용자 사례로 결과를 직접 확인해 문제를 고침. 예를 들어 외출·대화 부담이 큰 사용자가 '일자리·취업'을 골라도 취업 지원이 하나도 나오지 않는 경우를 찾아, 고른 관심 분야마다 최소 한 개는 보이도록 규칙을 추가함. 행정구역 개편으로 옛 지역 코드를 쓰면 후보가 빠지는 문제도 찾아 코드 대조 테스트를 넣음.
- 데이터 검증: 수집한 정책·센터 데이터의 항목별 채움 비율과 지역 코드를 점검 도구로 확인하고, 마감되거나 지난 공고가 추천에 섞이지 않는지 테스트로 확인함(현재 정책 2,335개·프로그램 137개 제공).
- 공고 추출 검증: AI가 뽑은 항목마다 원문 근거 구절을 함께 받아, 근거가 실제 본문에 있을 때만 저장함(프로그램 137개 중 127개 통과, 나머지는 수집한 원문 정보로 표시).
- 환각 방지: 서버가 조건으로 거른 데이터 안에서만 답하게 하고, 데이터로 확인되지 않은 조건은 "추가 확인이 필요해요"로 안내함. 모든 추천에 공식 공고 링크를 표시함. AI 호출은 20초 제한과 1회 재시도를 두고, 실패하면 지어낸 답 대신 오류를 알림.
- 안전: 자살·자해 표현은 AI 판단에 맡기지 않고 규칙으로 감지해 109 등 상담 연락처를 먼저 안내함. 이 안내는 AI 호출 실패나 사용량 제한과 관계없이 항상 나가도록 함. 화면에 AI가 답변한다는 사실을 표시함.
- 개인정보: 로그인 없이 이용하며 설문·대화는 서버에 저장하지 않음. 추천 조건으로는 나이·지역·취업 상태·학력만 AI에 전달하고, 신청 초안 작성 시 이름·연락처는 [이름]처럼 바꿔 보냄. 시연·영상에는 가상 데이터만 사용함. API 키는 환경변수로만 관리함.
- 남은 한계: 소득 조건은 판정하지 않고 확인 필요로 표시함. 청년센터 프로그램은 서울 중심으로 수집됨. 신청 대행은 시연용 신청서에만 연결됨. 데이터 수집 시점은 아직 화면에 표시하지 않음. 대화 자유 입력의 개인정보 마스킹은 향후 적용 예정임.
