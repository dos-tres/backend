# 조이 AI 비서 — 백엔드 요구사항 업데이트

업데이트: 2026-11-18 (한국 시간)
상태: 사용자 요청 반영 기록. 기능 방향은 반영하며, 문항·산식·기술 구현은 아래 미확정 항목에 따라 구체화한다.

## 1. 제품 방향

사용자의 짧고 정리되지 않은 말에서도 필요한 도움을 파악하고, 선택형 확인을 거쳐 정책·프로그램 탐색부터 기관 문의, 신청 준비, 일정 관리, 참여 후 다음 행동까지 이어지는 실행형 AI 비서를 만든다. 피클을 벤치마킹하려는 사용자 의도를 반영한다. 피클의 실제 기능·기술에 대한 조사는 아직 완료하지 않았다.

## 2. 가입 시 현재 상태 체크 — 추가 요구사항

- 회원가입 또는 첫 이용 시 짧은 선택형 상태 체크를 제공한다.
- 기본 자격 정보(연령·거주 지역·재학/취업 상태)와 현재 생활 상태, 참여 준비도, 비서 이용 선호를 구분한다.
- I5에서 논의했던 경제·참여·외출·교류·지원망의 다섯 관점을 참고한다. 기존 지역·집단 참고지수의 산식을 개인에게 그대로 적용하지 않는다.
- 현재 단계에서는 서비스 자체 상태 체크로 설계한다. 공인 개인 진단척도나 검증된 고립 진단으로 표시하지 않는다.
- 상태 요약이 이후 추천과 질문 방식, 실행 지원에 실제로 반영되어야 한다.

### 문항 초안 — 확정 전

| 영역 | 질문 예시 |
| --- | --- |
| 경제 | 요즘 생활비나 취업 준비 비용이 얼마나 부담돼요? |
| 참여 | 최근 학교·일·모임처럼 정기적으로 하는 활동이 있나요? |
| 외출 | 요즘 필요한 일 외에도 밖에 나가는 편인가요? |
| 교류 | 편하게 이야기 나누는 시간이 충분하다고 느껴요? |
| 지원망 | 곤란한 일이 생겼을 때 도움을 부탁할 사람이 있나요? |

별도로 현재 상태에 대한 만족도·바꾸고 싶은 마음·대면 활동 부담·원하는 도움을 확인한다. 혼자 지내는 선호만으로 문제나 고립을 추정하지 않는다.

### 이용 방식

- 한 번에 질문 하나, 선택지 중심으로 진행한다.
- 자유 입력·모르겠음·응답하지 않음·나중에 진행하기를 제공하는 방향으로 설계한다.
- 조이가 이해한 상태 요약을 보여주고 사용자가 수정할 수 있게 한다.
- 상태는 고정된 성격으로 취급하지 않고 이후 수정·재체크할 수 있게 한다.

## 3. 적게 말해도 진행되는 대화

- 이미 확인한 정보는 반복해서 묻지 않는다.
- 모호한 표현에서 의도와 부담 요인을 추출하되, 추정과 사용자 확인 사실을 구분한다.
- 지금 필요한 정보만 추가로 질문한다.
- 선택지와 자유 입력을 함께 제공한다. 사용자가 선호하는 방식으로 전환할 수 있다.
- 정보가 부족하면 미확인 상태를 유지하며, 소득·자격·참여 의사를 만들어내지 않는다.

## 4. 실행 지원과 전화 문의 대행 — 범위 변경

이전 기획의 전화 대행 제외 방침을 수정하고, 전화 문의 대행을 구현 검토 대상에 포함한다.

- 공고의 자격·참여 방식·준비물 등 사용자가 궁금해하는 내용을 정리한다.
- 공개 정보로 확인 가능한 내용을 우선 확인하고, 남은 질문에 기관 문의를 제안한다.
- 전화할 기관·번호·질문·전달할 정보를 사용자에게 보여주고 실행 확인을 받는다.
- 실제 통화 연동은 기술·제공 서비스 확인 후 구현한다. 미연결 상태를 실제 통화 완료로 표시하지 않는다.
- 문의 결과는 확인된 답변·미확인 질문·다음 행동으로 구분한다.
- 부재중·통화 실패·일부 답변만 확보한 경우를 기록하고 사용자에게 알린다.
- 전화 확인은 자동 신청·예약·개인정보 제공까지 포괄하는 승인으로 취급하지 않는다.

## 5. 전체 흐름

가입 및 기본 정보 → 선택형 상태 체크 → 상태 요약 확인 → 첫 행동 제안 → 필요한 정보 확인 → 정책·프로그램 탐색 → 조건 대조 → 사용자 선택 → 기관 문의/신청 준비 → 신청 이력·일정 저장 → 참여 여부·소감 확인 → 원할 때 다음 활동 제안.

사용자는 상태 체크를 나중에 진행하거나 정책·활동 목록에서 직접 시작할 수도 있다.

## 6. 백엔드에 추가할 기능과 데이터

| 기능 | 저장·처리할 내용 |
| --- | --- |
| 상태 체크 | 문항·선택지 버전, 응답, 응답 시점, 완료/부분 응답 |
| 상태 요약 | 영역별 응답 요약, 사용자 수정, 요약 근거 |
| 개인화 | 필요한 지원, 참여 준비도, 대화 방식, 도움 선호 |
| 대화 맥락 | 사용자 확인 정보, 추정 정보, 아직 모르는 정보 |
| 실행 업무 | 목표, 필요한 정보, 실행 단계, 다음 행동 |
| 실행 확인 | 확인받은 대상·질문·전달 정보·시각·업무 버전 |
| 문의 작업 | 기관, 번호, 질문, 시도, 통화 결과, 미확인 사항 |
| 실행 결과 | 성공·부분 성공·실패, 근거, 사용자에게 보여줄 결과 |

업무 상태 초안: 정보 확인 중 / 사용자 확인 대기 / 실행 대기 / 실행 중 / 완료 / 일부 완료 / 실패 / 취소.
업무 상태는 실제 실행 결과로 변경한다. 통화 결과나 신청 완료를 AI가 임의로 확정하지 않는다.

상태 체크 응답과 대화는 사용자별 접근 권한을 적용하고, 저장 목적 안내 및 수정·삭제 경로를 명세에 포함한다.

## 7. 아직 결정할 내용

1. 최종 문항·선택지·회상 기간·문항 수.
2. I5 원문 및 구성 근거 확인, 별도 검증 척도 도입 여부.
3. 점수 제공 여부와 해석 기준. 현재 확정된 총점·가중치·위험등급은 없음.
4. 상태 응답을 추천에 반영할 규칙. 다섯 영역에서 특정 지원을 자동 배정하지 않음.
5. 실제 전화 연동 제공 서비스·기술·운영 방식·재시도 정책.
6. 상태 체크의 구체적인 동의·보관·삭제 정책.

## 8. 다음 명세 작성 시 적용

백엔드 기능 명세·DB·API·프론트 첫 이용 흐름을 구체화할 때 이 요구사항을 반영한다. 이번 업데이트는 요구사항 기록이며, 실제 백엔드·전화 연동·프론트 기능 구현 완료를 뜻하지 않는다.
