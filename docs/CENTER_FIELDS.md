# 청년센터 API (getSpace) 필드 정의

> 로컬 `ai_hackathon` 폴더에서 옮겨 온 문서다. 경로는 저장소 구조 기준으로 바꿨다 (2026-11-19). 추천 전체 흐름은 [RECOMMENDATION.md](RECOMMENDATION.md).

온통청년 `getSpace`(청년공간·센터) 응답의 필드 정의다. 코드값은 실제 데이터 예시로 구조를 풀어 설명한다.
수치는 2026-11-18에 수집한 251건 기준이다. 정책 API는 [POLICY_FIELDS.md](POLICY_FIELDS.md)를 본다.

---

## 요청과 응답

```
GET https://www.youthcenter.go.kr/go/ythip/getSpace
    ?apiKeyNm=<센터 API 키>&pageNum=1&pageSize=1000&rtnType=json
```

```json
{
  "resultCode": 200,
  "resultMessage": "성공적으로 데이터를 가지고 왔습니다.",
  "result": {
    "pagging": { "totCount": 710, "pageNum": 1, "pageSize": 1000 },
    "youthPolicyList": [
      {
        "cntrSn": "10326",
        "cntrNm": "동래구청년어울림센터",
        "cntrAddr": "부산광역시동래구금강로",
        "cntrDaddr": "129",
        "cntrTelno": "051-997-5003",
        "cntrUrlAddr": "",
        "stdgCtpvCd": "26",
        "stdgCtpvCdNm": "부산광역시",
        "stdgSggCd": "260",
        "stdgSggCdNm": "동래구"
      }
    ]
  }

```

- 목록 키 이름이 정책 API와 같은 `youthPolicyList`다. 센터 목록인데도 이 이름을 쓴다.
- 정책 API와 **인증키가 다르다**(`YOUTH_CENTER_API_KEY`).

### ⚠ 수집할 때 주의할 점

**1. `pageSize=1000`으로 한 번에 받는다.** 서버 정렬이 요청할 때마다 달라서, 여러 페이지로 나누면 중복과 누락이 생긴다.

| pageSize | 받은 행 | 고유 센터 | 빠진 센터 |
|---|---|---|---|
| 10 | 251 | 205 | 46 |
| 50 | 251 | 220 | 31 |
| 100 | 251 | 221 | 30 |
| **1000** | **251** | **251** | **0** |

**2. `totCount`는 710이지만 받을 수 있는 건 251곳이 전부다.**
- 지역이나 이름으로 거르는 파라미터를 7종 넣어 봤다(`stdgCtpvCd`, `ctpvCd`, `zipCd`, `stdgCtpvCdNm`, `stdgSggCd`, `cntrNm`, `srchWord`). 모두 무시되고 같은 결과가 왔다. **지역별 조회는 지원되지 않는다.**
- 페이지 크기 8가지로 받은 결과를 합쳐도 251곳에서 늘지 않는다.
- `cntrSn`이 677~10326으로 띄엄띄엄하다. 710은 운영을 마쳤거나 공개하지 않는 센터까지 센 숫자로 보인다(추정).

## 코드 구조 읽는 법

### 지역코드 — 시도(2) + 시군구(3)를 붙이면 5자리 시군구 코드

센터는 시도와 시군구를 **따로** 준다. 둘을 붙이면 정책 `zipCd`와 같은 5자리 코드가 된다.

```
stdgCtpvCd = "41"   (경기도)
stdgSggCd  = "463"  (용인시 기흥구)
             ─────
붙인 값    = "41463"  ← 정책 zipCd와 같은 체계 (법정동코드 앞 5자리)
```

- `stdgSggCd`는 항상 3자리이고 `stdgCtpvCd`는 항상 2자리다. 251건 모두 그렇다.
- **센터에서 나오는 190종의 5자리 코드가 모두 정책 `zipCd`에 있다.** 그대로 같은 키로 쓸 수 있다.
- 시도 코드 16개의 목록은 [POLICY_FIELDS.md의 시도 코드](POLICY_FIELDS.md#3-지역코드-zipcd-5자리--시도2--시군구3)와 같다.

**일반구가 있는 시**는 이름에 시와 구가 함께 들어가고, 코드는 구 단위로 온다.

```
48121  stdgSggCdNm = "창원시 의창구"
41461  stdgSggCdNm = "용인시 처인구"   ┐
41463  stdgSggCdNm = "용인시 기흥구"   │ 앞 4자리 4146 → 용인시
41465  stdgSggCdNm = "용인시 수지구"   ┘
```

- 시 단위 코드(끝자리 `0`, 예: `41460`)로 들어간 센터는 없다.
- **세종**은 시군구가 따로 없다. `stdgSggCd="110"`, `stdgSggCdNm="세종특별자치시"`로 온다 → `36110`.

**센터 수가 많은 시군구**: `11350` 서울 노원구 6곳 · `26110` 부산 중구 4곳 · `26230` 부산 부산진구 4곳 · `30170` 대전 서구 4곳 · `52710` 전북 완주군 4곳

### 일련번호 `cntrSn`

- 숫자로 된 문자열이다(`"10326"`). 범위는 677~10326이고 번호 사이가 비어 있다.
- 구조가 있는 번호가 아니라 단순 일련번호로 보인다. PK로만 쓴다.

## 필드 정의

| 필드 | 설명 | 채움 | 형식 / 비고 |
|---|---|---|---|
| `cntrSn` | 센터 일련번호 (PK) | 100% | 숫자 문자열 |
| `cntrNm` | 센터 이름 | 100% | 이름이 겹치는 센터는 없다 |
| `cntrAddr` | 기본 주소 | 100% | 아래 주소 참고 |
| `cntrDaddr` | 상세 주소 | 63% | 건물 번호, 층 등 |
| `cntrTelno` | 전화번호 | 100% | 하이픈 포함 (`051-997-5003`) |
| `cntrUrlAddr` | 홈페이지 URL | 98% | 아래 URL 참고 |
| `stdgCtpvCd` | 법정 시도 코드 | 100% | 2자리 |
| `stdgCtpvCdNm` | 시도 이름 | 100% | 16개 |
| `stdgSggCd` | 법정 시군구 코드 | 100% | 3자리 — 시도 코드와 붙여서 쓴다 |
| `stdgSggCdNm` | 시군구 이름 | 100% | 일반구는 `"용인시 기흥구"`처럼 온다 |

**API에 없는 것:** 운영시간, 프로그램, 위도·경도, 운영 주체, 이메일.
→ 지도에 표시하려면 주소를 좌표로 바꾸는 작업(지오코딩)이 필요하다. 프로그램은 홈페이지에서 따로 수집해야 한다.

### 주소 — 형식이 제각각이다

```
"부산광역시동래구금강로"  + cntrDaddr "129"   ← 띄어쓰기 없음, 건물번호는 상세주소에
"경기도 수원시 팔달구 효원로 1"                 ← 기본 형식
"김해시 부곡로 57"                              ← 시도 이름 없음
"여수시 문수로117"                              ← 시도 없고 붙여 씀
```

- 시도 이름으로 시작하는 주소는 165건뿐이다(66%).
- 지오코딩할 때는 `stdgCtpvCdNm + stdgSggCdNm + cntrAddr + cntrDaddr`을 조합하는 게 안전하다(시도와 시군구가 겹쳐도 지오코더가 대부분 처리한다).

### 전화번호 형식

`999-999-9999` 193건 · `999-9999-9999` 25건 · `99-9999-9999` 21건 · `99-999-9999` 11건 · 그 외 1건. 모두 하이픈이 들어 있다.

### URL — 정리가 필요하다

| 상태 | 건수 | 예시 |
|---|---|---|
| `http(s)://`로 시작 | 239 | `https://hsyouthcenter.hsg.go.kr/` |
| 비어 있음 | 6 | |
| 정상이 아님 | 6 | `www.hampyeong.go.kr` (scheme 없음), `" https://gstartup.geri.re.kr/"` (앞에 공백), `"/ https://www.yuseong.go.kr/ysyouth/"` (앞에 `/ `) |
| 한글 도메인 | 3 | `http://www.꿈터.kr/` → punycode로 바꿔야 접속된다 |

정리 순서: 앞뒤 공백 제거 → 첫 `http` 앞의 글자 제거 → scheme이 없으면 `http://`를 붙임(대부분 https로 리다이렉트된다) → 한글 도메인은 IDNA로 인코딩.
`inspect_centers.py`의 `guess_url()`과 `to_ascii_url()`이 이 규칙을 따른다. 이렇게 하면 URL이 있는 245곳이 모두 진단 대상이 된다.

### 홈페이지 플랫폼 (프로그램 수집 방법을 정하는 근거)

플랫폼은 **접속한 뒤의 최종 URL 도메인**으로 판단한다. 자체 홈페이지라면 그다음 HTML 지문으로 CMS 종류를 판별한다.
본문에 있는 SNS 링크는 플랫폼 판단에 쓰지 않고 `sns_links` 칸에 따로 기록한다.

> 이전에는 HTML 본문에서도 플랫폼을 찾았다. 그래서 푸터에 인스타그램 링크만 있는 자체 홈페이지 107곳이 "instagram"으로 잘못 분류됐다.

접속에 성공한 238곳 중 **자체 홈페이지가 168곳(71%)**이고, 외부 플랫폼이 70곳이다.

| 구분 | 플랫폼 | 곳 수 | 프로그램 정보 수집 |
|---|---|---|---|
| 자체 | gov_site (지자체 `.go.kr`, `.do`) | 71 | 정적 HTML. 지자체 CMS 게시판 |
| 자체 | custom/unknown | 56 | 13곳은 JS 렌더링 필요 |
| 자체 | gnuboard | 25 | `/bbs/board.php?bo_table=` 구조라 공통 크롤러를 만들기 쉽다 |
| 자체 | imweb · wordpress · xe · cafe24 | 16 | |
| 외부 | naver_blog | 41 | ❌ `blog.naver.com`과 `rss.blog.naver.com`의 robots.txt가 모든 크롤러를 막고 AI/RAG 용도의 수집을 금지한다. 공식 네이버 검색 Open API를 검토한다 |
| 외부 | instagram | 26 | 일반 HTTP로는 게시물을 볼 수 없다. 별도 방법이 필요하다 |
| 외부 | naver_cafe · facebook | 3 | 로그인이 필요할 수 있다 |
| — | 접속 실패 | 7 | 404 ×3, 503, 타임아웃, DNS, SSL |

**자체 홈페이지 168곳의 상태**
- 144곳에서 프로그램 게시판 후보 링크를 찾았다(`program_links`). 예: 광진 청년아지트 `프로그램 안내 → /board/list.php?M2_IDX=...`
- 114곳에는 SNS 링크도 있다(`sns_links`). 인스타그램 123개, 네이버 블로그 105개, 유튜브 63개, 카카오채널 53개 링크.
- 게시판 후보도 SNS 링크도 없는 곳은 21곳이다.
- JS 렌더링이 필요한 곳은 19곳이다.

→ **자체 홈페이지 게시판 크롤링을 주 경로로 한다.** 네이버 블로그(41곳)와 인스타그램(26곳)은 크롤링하지 않는다.
네이버 블로그를 쓰는 곳 중에는 서울청년센터(오랑) 지점이 많다. 그래서 서울 커버리지는 별도로 해결해야 한다 → [CRAWLER.md](CRAWLER.md#-서울은-그누보드로-거의-수집되지-않는다)

## 로컬 서비스 조회 API (2026-11-21 추가, 미커밋)

GET /api/centers: q(검색어, 최대200자), district(구 이름, 최대80자). 서울만 조회. 응답 items/districts/source=file/dataset=runtime|seed/notice.
GET /api/centers/{id}: item/source/dataset/programs/programs_source/notice. 미존재404, 센터 파일 읽기 실패503.
센터 응답 필드: id/name/address/region_code/district/province/homepage/updated_at. 전화번호는 이 응답에 포함하지 않는다. 운영시간·거리·좌표를 추정하지 않는다.
프로그램은 기존 DB 우선/파일 대체 조회 결과 중 center_names의 공백 제거 정확 일치로 연결한다. 센터의 DB 저장 테이블은 아직 없다. 기본 수집본은 최신 실시간 API와 구분한다.

## 2026-11-21 · 센터 별칭으로 누락된 프로그램 복구

- 기존 공백 제거 정확 일치가 공식 센터명의 부가 이름을 처리하지 못해 관악·금천·서초 프로그램을 누락시켰다.
- 공식 서울청년센터 지점 이름을 키로 정규화한다. 관악의 신림동쓰리룸, 금천의 청춘삘딩, 서초의 괄호 공식명과 프로그램의 짧은 지점명을 연결한다. 같은 구의 별도 기관(관악청년청 등)에는 합치지 않는다.
- 수집 파일 기준 관악8/금천14/서초5건 복구, 실제 브라우저 관악 상세에서 DB공고8개 표시 확인. 센터 API2테스트 통과(별칭·기관 구분·연결 결과 회귀 포함). 서버 재시작·유지, 커밋/푸시/PR 변경 없음.
- 센터 ID가 serving 프로그램 필드에 남아 있지 않아 현재 공식 지점명으로 연결한다. 장기적으로 center_sns를 serving/DB 응답까지 유지하는 것이 필요하다. 기타 미수집 센터는 여전히 프로그램이 없을 수 있으며 기관 미운영으로 단정하지 않는다.

센터 응답 guide 필드와 공식 출처 보강은 [CENTER_GUIDES](CENTER_GUIDES.md)를 따른다. 원본 센터 수집 파일과 프로그램 DB는 그대로 유지한다.
